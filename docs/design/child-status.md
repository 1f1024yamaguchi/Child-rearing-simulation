# 子どものステータスと子どもカード

> 子ども（成績・趣味・体調・ストレス・勉強⇔遊び）の持ち方と、ステータス画面の作りを決める。
> 数値はすべて **調整前のたたき台**。特性・状態（風邪気味など）は [traits.md](traits.md) を参照。
> テスト・受験の時期と、進路・エンディングは [ending.md](ending.md) で決めた（5章）。

---

## 1. 誰が何を持つか

ストレスは人ごとに持つと決まっている（[../decisions/0005-per-person-stress.md](../decisions/0005-per-person-stress.md)）。
状態や特性も母・父・子に共通で付くので、**「人」に共通するものを1段まとめる**。

```
PersonStatus（母・父・子の共通の土台）
  表示名 / ストレス / 特性(Trait) / 状態(Condition)
   │
   ├ ParentStatus … 役職・月給・ライフ⇔ワーク（既存）
   └ ChildStatus  … 勉強⇔遊び・成績・趣味・体調

Household … 母・父・子の入れ物。親の平均バランス／平均ストレスもここで出す
```

> これにより、AGENTS.md の未決定項目「ストレスの持ち方の整理（`GameState.Stress` が世帯にひとつで旧仕様のまま）」も同時に片付く。
> `GameState.Stress` は使わなくなる。移行の段取りは [../code/architecture.md](../code/architecture.md) 3章に追記すること。

### ステータス一覧

| 項目 | 範囲 | 持ち主 | 動かすもの |
|---|---|---|---|
| ストレス | 0–100 | PersonStatus | 勉強⇔遊び／親のバランス／食事／イベント |
| 特性（永続） | リスト | PersonStatus | イベント |
| 状態（一時） | リスト | PersonStatus | イベント |
| 勉強⇔遊び | 0–1（0＝勉強） | ChildStatus | プレイヤー（スライダー） |
| 成績 | 0–100 | ChildStatus | 毎日の成長計算 |
| 趣味 | 種類＋経験値→Lv | ChildStatus | 毎日の成長計算／イベントで「発見」 |
| 体調 | 0–100 | ChildStatus | 毎日の成長計算／食事／イベント |
| 年齢 | — | GameState.AgeDays から計算 | GameClock |

趣味の種類は `なし / スポーツ / 音楽 / 芸術 / ゲーム / 読書`（たたき台。増やしてよい）。
熟練度は経験値から求める（既定：100 経験値で 1 レベル）。
**レベルは 0 始まり**。趣味が見つかっていても経験値が 0 のときは Lv.0 と表示する。

年齢（`AgeYears`）は **float で返す**。「8歳」のように切り下げるのは表示側の仕事。

`Household` は親だけを返す `Parents` と、親＋子を返す `Members` を持つ。
**この2つは呼ばれるたびに新しいリストを作らないこと。**
毎日全員をなめる処理（状態の日数減らしなど）から呼ばれるので、`yield return` で返すか、
内部でリストを使い回す形にする。

## 2. 書き込みの窓口はひとつにする（重要）

AGENTS.md ルール4「`GameState` を経由する」と同じ考え方を、人ごとのステータスでも守る。

- ストレスを変える → `AddStress(delta)`
- 成績を変える → `AddGrade(delta)`
- 体調を変える → `AddHealth(delta)`
- 趣味を伸ばす → `AddHobbyExp(delta)`

**外から値を直接書き換えない。** 理由は2つ。

1. 変更通知（イベント）がここから出るので、UI が自動で追従する。
2. **特性・状態の補正をここで掛ける。**「ストレスが上がりにくい」は `AddStress` の中で1回掛ければ、スライダー・食事・イベントすべてに効く。窓口を迂回されると効かなくなる。→ [traits.md](traits.md) 3章

### 通知は「表示が変わるときだけ」出す

ステータスは内部では float で持ち、外には丸めた整数を見せる。
成長の計算は毎日少しずつしか動かないので（成績なら 1日 +0.2）、
**丸めた整数が変わらない日は変更通知を出さない**。

```
変更前の丸めた値 ≠ 変更後の丸めた値  のときだけ Invoke する
```

理由：UI の `StatusListUI.SetStatus` は中でレイアウトを再構築するので、
毎日（＝実時間で毎秒）通知を出すと、表示は変わらないのに再構築だけが走る。

- 対象：`AddStress` / `AddGrade` / `AddHealth`。`SetStress` も同じ。
- `AddHobbyExp` はもともとレベルが変わったときだけ通知するのでこのままでよい。
- `SetStudyPlayBalance` はプレイヤー操作なので毎回通知してよい。

## 3. 勉強⇔遊びバランスの数値（たたき台）

[rules-and-stats.md](rules-and-stats.md) 3.5 の5段階の表は、スライダーが連続値なので **両端のあいだを直線で補間**して使う。端の値は表と一致する。

すべて **1ヶ月あたり**で書き、`÷30` して毎日適用する（1ヶ月は28〜31日なので月ごとに合計が少しずれる。差は許すと決定 → [../decisions/0009-real-calendar-months.md](../decisions/0009-real-calendar-months.md)）。`b` = 勉強⇔遊び（0＝勉強／1＝遊び）、`w` = 親2人のライフ⇔ワークの平均（0＝ライフ／1＝ワーク）。

**ただしストレスだけは 1日あたり**（÷30 しない）。親の `ParentStressSystem` と同じ単位に揃え、偏らせたら数十日で危険域に届くテンポにする（2026-10-04 決定）。

| 項目 | 1ヶ月あたりの式 |
|---|---|
| 成績 | `Lerp(+6, 0, b)` ＋ `Lerp(+2, −2, w)` 　→ さらに `× 体調/100`（プラスのときだけ） |
| 趣味経験値 | `Lerp(0, +30, b)` ＋ `Lerp(+2, −2, w)` 　→ マイナスにはしない |
| ストレス（**1日あたり**） | `Lerp(+5, −5, b)` ＋ `Lerp(−1, +2, w)` 　→ 親の平均ストレス > 70 なら さらに +1 |
| 体調 | 自然回復 +2 　→ 子ストレス > 70 なら −4 |

- 成績に体調を掛けているのは、rules-and-stats.md 5章「体調不良で低下」に対応。
- 親の平均ストレスによる上乗せは「ピリピリした家庭環境」に対応。
- 趣味は伸びるだけで減らない（イベントで下げたいときは Effect で明示的に下げる）。

**これらの値はすべて Inspector から触れるようにする。** ScriptableObject に外出しにするかは [../code/architecture.md](../code/architecture.md) の方針に合わせる。

## 4. 家出（ゲームオーバー）

- 子のストレスが **91 以上（＝限界）** の日を数える。
- 限界を下回ったらカウントは **0 に戻す**。
- カウントが規定日数に達したら家出 → 時間を止めてゲームオーバー。

**規定日数は未定。** 仮に 30 日（＝ゲーム内1ヶ月＝実時間30秒）。AGENTS.md の未決定リストにある項目。

### 家出は一度きり

**家出したらその時点でエンディング（ゲームオーバー）。ゲームはそこで終わる。**

家出の通知は **必ず1回だけ** 出す。一度家出したらフラグを立て、以後は日が進んでも判定を行わない。
時間を止めれば結果的に1回で済むが、後から一時停止やイベントが入ったときに二重で発火しないよう、
フラグで明示的に止めること。

### 将来変えるかもしれないこと（メモ。今は実装しない）

「家出＝即終了」ではなく、一定期間のペナルティにする案もある。

- 家出中はワークライフバランスを選べない
- 子どもがお金を勝手に持っていく
- しばらくしたら戻ってくる

この場合でも「家出が始まった瞬間の通知は1回だけ」は変わらないので、いまの作りのまま拡張できる。

UI では、カウントが 1 以上になったらステータス欄に「家出まで ○日」の行を出して警告する。0 に戻ったら行ごと消す。

## 5. 成績とテスト・受験

> **2026-10-19 更新**：テスト・受験の時期は決定済み。詳細は [ending.md](ending.md) 2.5章。

### テストと受験の時期（決定）

| 時期 | 内容 | 時間を止める？ |
|---|---|---|
| 小学校 7・12・3月 | 通知表（成績を見せるだけ。判定しない） | 止めない |
| 中学・高校 7・12・3月 | 学期末テスト（下の合格ラインで自動判定。中1〜高3で18回） | 止めない（通知だけ） |
| 中3の2月 | 高校受験（公立に受かるか。落ちたら私立） | 止める |
| 高3の7月／11〜12月／2月 | 進路決定／推薦の合否／一般入試の合否 | 止める |

受験の合否は進路ごとの合格ラインと合格率（確率）で決める。→ [ending.md](ending.md) 3.4・3.5章

### 学期末テストの合格ライン

- `ChildStatus` が **合格ライン**（既定 60%）を持ち、カードに表示する。
- いまの成績が合格ラインを下回っていれば、ステータス欄の「合格ライン」行に「不足」と出す。
- **判定は画面に出ている値（丸めた整数）で行う。** 内部の float で比べない。
  成績 59.6 のときに「60%」と表示しながら「不足」と出ると、プレイヤーに理由が説明できないため。
- この合格ラインは **学期末テスト用**。受験の合格ライン（進路ごと）とは別の値で、混ぜない。

### 評定

高校の学期末テスト（高1〜高3、計9回）の平均から評定（5段階）を出し、推薦・修学支援・奨学金の条件に使う。→ [ending.md](ending.md) 2.5章

### 不合格のときの扱い（決定済み）

**ゲームオーバーにはしない。** 進級できない、ではなく **進路の選択肢が狭まる** 方向で効かせる。

- 子のストレスが上がる
- 学期末テストの結果を記録し、巣立ちの日の職業判定で参照する（「合格ラインを下回った回数」が多いと研究者などの候補から外れる、など）。→ [ending.md](ending.md) 5章
- 受験の不合格を同じ回数に含めるかは **未定**（[ending.md](ending.md) 10章）

## 6. 子どもカードのUI

**大きさは親カードと同じ 200×250。** 3枚の高さを揃える。

```
┌─ 子ども　　　[注意] ┐   ← 名前＋ストレス段階バッジ
│ 8歳・スポーツが好き │   ← 年齢＋趣味の一行
│ 遊び ───●─── 勉強  │   ← 勉強⇔遊びスライダー（右が勉強）
│ 成績    ████░░ 68% │
│ ストレス ███░░░ 45% │   ← 3本のメーター
│ 体調    ████░░ 60% │
│ ┌─────────────────┐ │
│ │ 趣味   スポーツLv3│ │
│ │ 合格ライン 60% 不足│ │  ← ステータス欄（縦スクロール。既存の
│ │ 勉強が得意 成績+20%│ │     status_scroll / StatusListUI を流用）
│ │ 風邪気味   あと53日│ │
│ └─────────────────┘ │
└─────────────────────┘
```

### 勉強⇔遊びスライダーの向き

**スライダーは右が勉強。値はカード側で反転して渡す。**

- 内部データ（`ChildStatus.StudyPlayBalance`）：0＝勉強寄り、1＝遊び寄り（定義は変えない）
- 画面表示（uGUI Slider）：左（0）＝遊び、右（1）＝勉強
- `ChildCardUI` 内で反転を処理する：
  - スライダー操作時：`child.SetStudyPlayBalance(1f - sliderValue)`
  - 初期表示・値同期時：`studyPlaySlider.SetValueWithoutNotify(1f - child.StudyPlayBalance)`
  - Slider の Direction は親カードと見た目を揃えるため `Left To Right` のまま維持する。

### 右上のバッジ＝ストレス段階

> **2026-10-04 廃止。** ストレスゲージで足りるため、バッジは作らない。以下は記録として残す。

スケッチの「好調」「注意」は **ストレス値を分かりやすくしたもの**であって、風邪気味などの状態ではない。
風邪気味は下のステータス欄の「状態」行に出す。

[rules-and-stats.md](rules-and-stats.md) の段階にそのまま対応させる（表示名は仮）：

| ストレス | 段階 | バッジ表示 | 色 |
|---|---|---|---|
| 0–30 | 良好 | 好調 | 緑 |
| 31–70 | 普通 | 普通 | 灰 |
| 71–90 | 危険 | 注意 | 赤 |
| 91–100 | 限界 | 限界 | 濃い赤 |

**このバッジは母親・父親カードにも同じものを付ける。**

### 使い回すもの

- ステータス欄のスクロールと行は、既存の `status_scroll` / `StatusListUI` / `StatusRowUI` をそのまま複製して使う。→ [../code/ui-scroll-patterns.md](../code/ui-scroll-patterns.md)
- **特性・状態は1件につき1行**で、左に名前・右に効果（状態は残り日数）。書式は [traits.md](traits.md) 6章。親カードも同じ。
- メーター（ラベル＋バー＋数値）は3本とも同じ部品にする。親カードのストレスバーも将来これに寄せられる形が望ましい。
- カードのスクリプトは親の `ParentCardUI` と同じ作り（`Start` で `Household` から取得 → 購読 → 表示するだけ）。計算はしない。
