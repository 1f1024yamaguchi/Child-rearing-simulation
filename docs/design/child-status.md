# 子どものステータスと子どもカード

> 子ども（成績・趣味・体調・ストレス・勉強⇔遊び）の持ち方と、ステータス画面の作りを決める。
> 数値はすべて **調整前のたたき台**。特性・状態（風邪気味など）は [traits.md](traits.md) を参照。
> テスト・受験の時期は **未定**（6章）。

---

## 1. 誰が何を持つか

ストレスは人ごとに持つと決まっている（[../decisions/0005-per-person-stress.md](../decisions/0005-per-person-stress.md)）。
状態や特性も母・父・子に共通で付くので、**「人」に共通するものを1段まとめる**。

```
PersonStatus（母・父・子の共通の土台）
  表示名 / ストレス / 特性(Trait) / 状態(Condition)
   │
   ├ ParentStatus … 役職・月給・ライフ⇔ワーク（既存）
   └ ChildStatus  … 勉強⇔遊び・成績・趣味・体調

Household … 母・父・子の入れ物。親の平均バランス／平均ストレスもここで出す
```

> これにより、AGENTS.md の未決定項目「ストレスの持ち方の整理（`GameState.Stress` が世帯にひとつで旧仕様のまま）」も同時に片付く。
> `GameState.Stress` は使わなくなる。移行の段取りは [../code/architecture.md](../code/architecture.md) 3章に追記すること。

### ステータス一覧

| 項目 | 範囲 | 持ち主 | 動かすもの |
|---|---|---|---|
| ストレス | 0–100 | PersonStatus | 勉強⇔遊び／親のバランス／食事／イベント |
| 特性（永続） | リスト | PersonStatus | イベント |
| 状態（一時） | リスト | PersonStatus | イベント |
| 勉強⇔遊び | 0–1（0＝勉強） | ChildStatus | プレイヤー（スライダー） |
| 成績 | 0–100 | ChildStatus | 毎日の成長計算 |
| 趣味 | 種類＋経験値→Lv | ChildStatus | 毎日の成長計算／イベントで「発見」 |
| 体調 | 0–100 | ChildStatus | 毎日の成長計算／食事／イベント |
| 年齢 | — | GameState.AgeDays から計算 | GameClock |

趣味の種類は `なし / スポーツ / 音楽 / 芸術 / ゲーム / 読書`（たたき台。増やしてよい）。
熟練度は経験値から求める（既定：100 経験値で 1 レベル）。

## 2. 書き込みの窓口はひとつにする（重要）

AGENTS.md ルール4「`GameState` を経由する」と同じ考え方を、人ごとのステータスでも守る。

- ストレスを変える → `AddStress(delta)`
- 成績を変える → `AddGrade(delta)`
- 体調を変える → `AddHealth(delta)`
- 趣味を伸ばす → `AddHobbyExp(delta)`

**外から値を直接書き換えない。** 理由は2つ。

1. 変更通知（イベント）がここから出るので、UI が自動で追従する。
2. **特性・状態の補正をここで掛ける。**「ストレスが上がりにくい」は `AddStress` の中で1回掛ければ、スライダー・食事・イベントすべてに効く。窓口を迂回されると効かなくなる。→ [traits.md](traits.md) 3章

## 3. 勉強⇔遊びバランスの数値（たたき台）

[rules-and-stats.md](rules-and-stats.md) 3.5 の5段階の表は、スライダーが連続値なので **両端のあいだを直線で補間**して使う。端の値は表と一致する。

すべて **1ヶ月あたり**で書き、`÷30` して毎日適用する。`b` = 勉強⇔遊び（0＝勉強／1＝遊び）、`w` = 親2人のライフ⇔ワークの平均（0＝ライフ／1＝ワーク）。

| 項目 | 1ヶ月あたりの式 |
|---|---|
| 成績 | `Lerp(+6, 0, b)` ＋ `Lerp(+2, −2, w)` 　→ さらに `× 体調/100`（プラスのときだけ） |
| 趣味経験値 | `Lerp(0, +30, b)` ＋ `Lerp(+2, −2, w)` 　→ マイナスにはしない |
| ストレス | `Lerp(+6, −5, b)` ＋ `Lerp(−3, +6, w)` 　→ 親の平均ストレス > 70 なら さらに +3 |
| 体調 | 自然回復 +2 　→ 子ストレス > 70 なら −4 |

- 成績に体調を掛けているのは、rules-and-stats.md 5章「体調不良で低下」に対応。
- 親の平均ストレスによる上乗せは「ピリピリした家庭環境」に対応。
- 趣味は伸びるだけで減らない（イベントで下げたいときは Effect で明示的に下げる）。

**これらの値はすべて Inspector から触れるようにする。** ScriptableObject に外出しにするかは [../code/architecture.md](../code/architecture.md) の方針に合わせる。

## 4. 家出（ゲームオーバー）

- 子のストレスが **91 以上（＝限界）** の日を数える。
- 限界を下回ったらカウントは **0 に戻す**。
- カウントが規定日数に達したら家出 → 時間を止めてゲームオーバー。

**規定日数は未定。** 仮に 30 日（＝ゲーム内1ヶ月＝実時間30秒）。AGENTS.md の未決定リストにある項目。

UI では、カウントが 1 以上になったらステータス欄に「家出まで ○日」の行を出して警告する。0 に戻ったら行ごと消す。

## 5. 成績とテスト・受験

**テストの時期は未定。** 決まるまでは、以下だけ作っておく。

- `ChildStatus` が **合格ライン**（既定 60%）を持ち、カードに表示する。
- いまの成績が合格ラインを下回っていれば、ステータス欄の「合格ライン」行に「不足」と出す。

時期が決まったら、「何日目に／何%以上」の組を並べたスケジュールを足すだけで動く形にしておく。

### 不合格のときの扱い（決定済み）

**ゲームオーバーにはしない。** 進級できない、ではなく **進路の選択肢が狭まる** 方向で効かせる。

- 子のストレスが上がる
- 「合格ラインを下回った回数」を記録し、20歳のエンディング判定で参照する（博士・学者ルートから外れる、など）

エンディング判定そのものの設計は未着手。[rules-and-stats.md](rules-and-stats.md) 1章の分岐表とセットで決める。

## 6. 子どもカードのUI

**大きさは親カードと同じ 200×250。** 3枚の高さを揃える。

```
┌─ 子ども　　　[注意] ┐   ← 名前＋ストレス段階バッジ
│ 8歳・スポーツが好き │   ← 年齢＋趣味の一行
│ 勉強 ───●─── 遊び  │   ← 勉強⇔遊びスライダー
│ 成績    ████░░ 68% │
│ ストレス ███░░░ 45% │   ← 3本のメーター
│ 体調    ████░░ 60% │
│ ┌─────────────────┐ │
│ │ 趣味   スポーツLv3│ │
│ │ 合格ライン 60% 不足│ │  ← ステータス欄（縦スクロール。既存の
│ │ 勉強が得意 成績+20%│ │     status_scroll / StatusListUI を流用）
│ │ 風邪気味   あと53日│ │
│ └─────────────────┘ │
└─────────────────────┘
```

### 右上のバッジ＝ストレス段階

スケッチの「好調」「注意」は **ストレス値を分かりやすくしたもの**であって、風邪気味などの状態ではない。
風邪気味は下のステータス欄の「状態」行に出す。

[rules-and-stats.md](rules-and-stats.md) の段階にそのまま対応させる（表示名は仮）：

| ストレス | 段階 | バッジ表示 | 色 |
|---|---|---|---|
| 0–30 | 良好 | 好調 | 緑 |
| 31–70 | 普通 | 普通 | 灰 |
| 71–90 | 危険 | 注意 | 赤 |
| 91–100 | 限界 | 限界 | 濃い赤 |

**このバッジは母親・父親カードにも同じものを付ける。**

### 使い回すもの

- ステータス欄のスクロールと行は、既存の `status_scroll` / `StatusListUI` / `StatusRowUI` をそのまま複製して使う。→ [../code/ui-scroll-patterns.md](../code/ui-scroll-patterns.md)
- **特性・状態は1件につき1行**で、左に名前・右に効果（状態は残り日数）。書式は [traits.md](traits.md) 6章。親カードも同じ。
- メーター（ラベル＋バー＋数値）は3本とも同じ部品にする。親カードのストレスバーも将来これに寄せられる形が望ましい。
- カードのスクリプトは親の `ParentCardUI` と同じ作り（`Start` で `Household` から取得 → 購読 → 表示するだけ）。計算はしない。
