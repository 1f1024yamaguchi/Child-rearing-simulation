# イベント一覧

> メリット（子育てを優位にする）とデメリット（風邪など）の両方。**効果はすべてたたき台。**
> 発生方法は「ランダム抽選＋条件（年齢・お金・体調・季節など）で確率が変動」を想定（**発生ロジックは未確定**）。
> 制度そのものの詳細・自己負担は [support-systems.md](support-systems.md) を参照。

## 1. メリットイベント

### 政府の制度
| イベント | 発生条件 | 効果 |
|---|---|---|
| 児童手当 | 毎月（年齢で額変動） | お金 +（子が中学生まで） |
| 出産育児一時金 | 出産時 | お金 +（まとまった額） |
| 幼児教育・保育の無償化 | 子が3〜5歳 | 保育料の支出が0に |
| 医療費助成 | 通院・入院イベント時 | 医療費の支出を軽減 |
| 児童扶養手当 | 特定の家庭状況 | お金 + |

### 自治体の制度
| イベント | 発生条件 | 効果 |
|---|---|---|
| 子育て支援センター | 申込 | 親ストレス −、相談で不安解消 |
| 一時預かり保育 | 申込 | 親の時間確保 → 仕事とストレスを両立しやすく |
| 学童保育 | 子が小学生 | 親がワーク寄りでも子を放置しない（成績維持） |
| 予防接種の補助 | 定期 | 体調低下イベントの発生率ダウン |
| 給食費・教材費の補助 | 就学中 | 支出減 |
| 図書館・地域イベント | 不定期 | 子の成績 or 趣味 + |

### 便利なアプリ / サービス
| イベント | 発生条件 | 効果 |
|---|---|---|
| オンライン学習アプリ | 導入（課金） | 子の成績 +（毎月わずかな支出） |
| 家計簿アプリ | 導入 | 支出が見える化、無駄遣いイベント減 |
| フリマアプリ | 不用品発生時 | お金 +（不要になったベビー用品など） |
| 時短家電・デリバリー | 導入（支出） | 親の時間 + → ストレス − |
| 育児記録・見守りアプリ | 導入 | 体調異変の早期発見（重症化を防ぐ） |

## 2. デメリットイベント

| イベント | 発生条件 | 効果 |
|---|---|---|
| 風邪・インフルエンザ | ランダム（冬に確率↑、予防接種で↓） | 子の体調 −、医療費、看病で親ストレス +・仕事欠勤（月給 −） |
| ケガ・骨折 | ランダム（活発な子で↑） | 体調 −、医療費、趣味（スポーツ）一時停止 |
| 虫歯・アレルギー | 食事の質が低い月が続くと↑ | 体調 −、通院の支出 |
| 保育園からの呼び出し | 就園中ランダム | 仕事中断（ワーク寄りだと月給ダメージ大） |
| イヤイヤ期・反抗期 | 特定の年齢帯 | 親ストレス +、対応の選択肢イベント |
| 待機児童（入園できない） | 都市部設定・年度替わり | 親が仕事をセーブせざるを得ない（月給 −） |
| 家電の故障・急な出費 | ランダム | お金 −（家計簿アプリがあれば軽減余地） |
| 物価高・値上げ | 不定期 | 食事など支出が一時的に増加 |
| 学校でのトラブル | 就学中ランダム | 子のメンタル/成績 −、対応イベント |

## 3. 行動選択

イベントが発生したらカードで提示し、プレイヤーが行動を選ぶ。**選択画面を開いている間はゲーム内時間を止める**（[../decisions/0004-pause-during-decisions.md](../decisions/0004-pause-during-decisions.md)）。効果を読み比べている間に日が進むと、比べること自体が罰になるため。

### カードの構成

```
[メリット / デメリット のラベル]
 アイコン
 タイトル          例：「みらいが風邪をひいた」
 ひとこと説明       例：「熱があるみたい。病院で診てもらう？ それとも家で様子を見る？」
 効果チップ         例：体調 −15 ／ ストレス +8
 選択肢ボタン ×2    例：「病院に行く（医療費 8,000円・助成適用前）」／「家で様子を見る」
```

- **選択肢は2つを基本**にする。読んで比べられる量に収める。
- 効果チップは `Effect` のリストから自動生成する。手書きしない。→ [effects.md](effects.md) 5章
- ストレスは人ごとに持つので、チップは対象が分かる形で出す（「親ストレス −10」「子ストレス −5」）。全員に同じ量が入るときだけ「ストレス −5」にまとめる。→ [../decisions/0005-per-person-stress.md](../decisions/0005-per-person-stress.md)

### 選択肢のデータ

**各イベントは選択肢を持ち、選択肢は `List<Effect>` を持つだけ。** イベント側で `GameState` を直接叩かない。→ [effects.md](effects.md)

```
イベント「みらいが風邪をひいた」
├ 選択肢「病院に行く」      : [ Money -8000（保険診療の自己負担）, Health +15 → Child ]、insuredMedicalExpense = true
└ 選択肢「家で様子を見る」  : [ Stress +8 → Child, BadEventRate +5% (Days 7) ]
```

こうしておけば、後から「成績が下がる」「趣味が一時停止する」といった効果を**選択肢のデータに足すだけ**で増やせる。数値も効果も今後変わる前提なので、ここは守ること。

`EventChoice.insuredMedicalExpense` が true の選択肢では、負の Money 効果を保険診療の自己負担として扱う。子ども医療費助成が申請済みかつ対象年齢なら助成後の支払額と助成額を家計簿に記録する。保険適用外の費用にはこのフラグを付けない。既存の「病院に行く」選択肢には設定済み。

> 子どもの名前は「みらい」。イベント文面で名前を使うときは、ハードコードせず1箇所から参照できるようにしておく（将来プレイヤーが名前を決められるようにする余地を残すため）。

## 4. 設計メモ

- **メリットとデメリットは連動させると深みが出る**：
  - 例）予防接種の補助（メリット）を受けておくと、風邪イベント（デメリット）の確率が下がる。
  - 例）一時預かり保育（メリット）があると、保育園の呼び出し（デメリット）のダメージを減らせる。
- **「知っていれば得をする」構造**が、この企画のテーマ（制度・アプリを知る）と噛み合う。
  - 制度を知らずに見逃す／申請して活用する、という選択で差が出るようにする。
- 発生確率は 年齢・季節・お金・体調・過去の選択 で変動させ、毎回違う展開に。

## 5. 発生率の補正と発生条件（実装済み）

> 数値・段階の区切りはたたき台。`EventManager` の抽選は6章。経緯は [../decisions/0029-event-rate-store-and-conditions.md](../decisions/0029-event-rate-store-and-conditions.md)。

### 発生率の補正（`EventRateModifiers`）

- `EffectKind.GoodEventRate` / `BadEventRate`（単位は％ポイント）を `EffectApplier` が `EventRateModifiers` に登録する。以前はログを出すだけで、どこにも効いていなかった。
- 期間は `Effect.duration` に従う。`ThisMonth` は登録日から月末まで、`Days` は登録日から `days` 日間。`Instant` は意味がないので無視する（警告ログ）。
- 対象（`target`）は見ない。発生率は世帯全体のもの。
- 抽選側は `EventRateModifiers.TotalPercent(kind)` を読む。Effect 由来の補正に、家族全員の特性・状態が持つ補正（加算のみ）を足した値。→ [traits.md](traits.md) 3章
- セーブする（`EventManager` が一緒に保存。7章）。

### 発生条件（`EventConditionSO` の部品）

イベントの `conditions` に入れて使う。すべて満たしたときだけ発生候補になる。

| 部品 | 内容 | 例 |
|---|---|---|
| `AgeRangeCondition` | 子の満年齢が `minAgeYears`〜`maxAgeYears`（両端を含む）。年齢が分からない環境では絞らない | 0〜5歳 → 0 と 5 |
| `StressLevelCondition` | `source`（子／母／父／親の平均）のストレス段階が `minLevel`〜`maxLevel`。段階の区切りは [rules-and-stats.md](rules-and-stats.md)。世帯が無い環境では絞らない | 子が「危険」以上 → Child・危険・限界 |

## 6. 月ごとの抽選と0〜5歳のイベント（実装済み・数値はすべてたたき台）

経緯は [../decisions/0030-monthly-independent-event-lottery.md](../decisions/0030-monthly-independent-event-lottery.md)。

### 抽選の流れ

1. 月初に食事を選ぶと（食事の `BadEventRate` / `GoodEventRate` が `EventRateModifiers` に登録されたあと）、`EventManager.ScheduleForMeal` がその月の抽選をする。
2. **悪いイベントと良いイベントは別々に抽選する。** 片方だけ起きる月も、何も起きない月もある。同じ月に2回は抽選しない。
3. 当たった分を、今日より後の別々の日に予約する（同じ日に2つ重ねない）。
4. 予約日が来たら、その日の条件（年齢・ストレス）で出せるイベントを重み付きで1つ選び、**当たった側のカードだけ**を出す。直前に出したものは、他に候補があれば除く。

### 当たる確率（1回の抽選あたり）

```
確率(%) ＝ clamp( (基本確率 ＋ 発生率補正の合計) × ストレス段階の倍率 , 0 , 上限 )
```

| 項目 | 悪い | 良い |
|---|---|---|
| 基本確率 | 35% | 40% |
| 1か月の抽選回数（上限） | 2 | 1 |
| ストレス倍率（良好／普通／危険／限界） | 0.7／1.0／1.5／2.0 | 1.0／1.0／1.0／1.0 |
| 確率の上限 | 90% | 90% |

- 発生率補正の合計は `EventRateModifiers.TotalPercent`。食事（安価：悪い +5、高価：良い +5）や、イベントの選択肢・特性が足す。
- ストレス段階は、**家族のうち一番ストレスが高い人**の段階。
- 良いイベントはストレスで減らさない。代わりに、ストレスが高いときの救済は **イベント側の発生条件**で出す（下の「夫婦でじっくり話し合った」）。
- 値はすべて `EventManager` の Inspector で変えられる。

### 0〜5歳のイベント（たたき台）

イベントは `Assets/Maruyama/Resources/Events/` のアセット。`EventManager` が自動で読み込むので、**足すときはここにアセットを置くだけ**でよい（シーンの一覧への登録は不要）。`重み`は条件を満たしたイベントの中での選ばれやすさ。

| 種類 | イベント | 年齢 | 重み | 選択肢と効果 |
|---|---|---|---|---|
| 悪い | みらいが風邪をひいた（既存） | 0〜5 | 1 | 病院に行く：医療費 −8,000（助成対象）／家で様子を見る：子の体調 −15・子ストレス +8 |
| 悪い | みらいが転んでケガをした | 1〜5 | 1 | 病院に行く：医療費 −5,000（助成対象）／家で手当てする：子の体調 −8・子ストレス +5 |
| 悪い | 夜泣きが続いている | 0〜2 | 1.5 | 夫婦で交代であやす：親ストレス +3・子ストレス −2／母がひとりで対応する：母ストレス +10 |
| 悪い | イヤイヤ期が始まった | 1〜3 | 1 | 気持ちに付き合う：親ストレス +5・子ストレス −3／叱る：子ストレス +8・親ストレス +2 |
| 悪い | 洗濯機が壊れた | 0〜5 | 1 | 買い替える：−40,000／修理して様子を見る：−12,000・親ストレス +4 |
| 良い | 一時預かり保育が使える（既存） | 0〜5 | 1 | 申し込む：−2,000／見送る：親ストレス −10・子ストレス −3（※下の注意） |
| 良い | 子育て支援センターに行ってみた | 0〜5 | 1 | 参加する：親ストレス −8・子ストレス −2／見送る |
| 良い | 公園でお友達ができた | 2〜5 | 1 | たくさん遊ばせる：子ストレス −8・親ストレス +2／早めに帰る：子ストレス +3 |
| 良い | ご近所からおさがりをもらった | 0〜3 | 1 | いただく：親ストレス −4／気持ちだけいただく |
| 良い | 家族でお出かけ | 0〜5 | 1 | 出かける：−3,000・全員ストレス −6／家でゆっくり：親ストレス −2 |
| 良い（救済） | 夫婦でじっくり話し合った | 0〜5・**親の平均ストレスが「危険」以上** | 3 | 家事の分担を見直す：親ストレス −12／実家に来てもらう：親ストレス −8・子ストレス −4 |

- 「夫婦でじっくり話し合った」は、[raw の「親子で相談」](../research/raw/maruyama-support.md)（ストレス条件で出て、選択で解決する）を0〜5歳向けにしたもの。
- アセットは `ChildRearing → イベント → 0〜5歳のイベントを作る`（`EventAssetBuilder`）で作った。すでにあるアセットは上書きしない。条件のアセットは `Assets/Maruyama/Data/Conditions/`。

### 未実装・未決定

- ~~固定イベント~~ → 7章で実装済み。
- **6歳以降のイベント。** 0〜5歳の外では、条件を満たすイベントが無いので何も起きない。
- ~~予約と補正はセーブしない。~~ → セーブする（7章。[ADR 0031](../decisions/0031-fixed-events-and-event-save.md)）。
- **食事で悪いイベントが減る度合い**は、いまの食事の補正（±5）だと小さい。ストレス倍率のほうが効く（食事はストレスも動かす）。足りなければ [food-system.md](food-system.md) の値を見直す。
- 既存の「一時預かり保育」は、効果が選択肢の逆についている可能性がある（ストレス軽減が「見送る」側、「申し込む」側は費用だけ）。意図を丸山さんに確認する。

## 7. 固定イベント（実装済み・日付と効果はすべてたたき台）

経緯は [../decisions/0031-fixed-events-and-event-save.md](../decisions/0031-fixed-events-and-event-save.md)。

### 仕組み

- 抽選とは別に、**決まった月日に必ず起きる**イベント。`EventData` の `trigger = Fixed` にして、`fixedMonth` / `fixedDay` / `fixedMinAgeYears` / `fixedMaxAgeYears` で日付を決める。
- 満年齢が「最小〜最大」の範囲の毎年、その月日に起きる。**最小と最大が同じなら1回だけ**（つかまり立ち、初めての言葉）。違えば毎年（誕生日、お年玉、お遊戯会）。
- 暦は **0歳1月1日が誕生日**（年齢は毎年1月1日に上がる）。→ `GameDate`
- 起きたかどうかは「イベントid@歳」で記録し、**セーブする**。ロードしても二重に起きない。
- 抽選のイベントと同じ日になった場合、あるいはダイアログが開いている間に日が来た場合は、**捨てずに順番待ち**にして、閉じたあとに出す。悪い1・良い1を1組にして出す。
- 固定イベントは抽選の候補には入らない（重み・直前の除外は使わない）。発生条件（`conditions`）は付ければ見る。

### 0〜5歳の固定イベント（たたき台）

アセットは `Assets/Maruyama/Resources/Events/`（`ChildRearing → イベント → 0〜5歳の固定イベントを作る`）。

| イベント | 日付 | 年齢 | 選択肢と効果 |
|---|---|---|---|
| つかまり立ちができた | 10月15日 | 0歳のみ | 拍手して喜ぶ：親ストレス −8 |
| 初めての言葉 | 3月10日 | 1歳のみ | 胸がいっぱいになる：親ストレス −8 |
| みらいの誕生日 | 1月1日 | 1〜5歳の毎年 | ケーキとプレゼントでお祝い：−5,000・全員ストレス −8／家で普通にお祝い：全員ストレス −3 |
| お年玉をもらった | 1月3日 | 1〜5歳の毎年 | 全部貯金する：+10,000／半分でおもちゃを買う：+5,000・子ストレス −6 |
| お遊戯会の日 | 12月15日 | 3〜5歳の毎年 | 客席から見守る：親ストレス −6・子ストレス −4 |

- 出どころは [raw の一覧](../research/raw/maruyama-support.md)（初めての言葉・初めて立つ・誕生日・お年玉・発表会）。raw に効果の大きさは無いので、数値は仮。
- 純粋に良いことが起きるだけのもの（つかまり立ち・初めての言葉・お遊戯会）は、選択肢を1つにした（見せかけの選択を作らないため）。
- 日付は、同じ日に重ならないように決めた。誕生日（1月1日）とお年玉（1月3日）が別の日なのはそのため。
- **入れていないもの**：卒園・小学校入学（6歳）、保育園・幼稚園の入園と習い事（選択と継続の費用が要る）、赤ちゃん誕生・命名。

### セーブ

`EventManager` がセーブに参加する（キー `"event"`、`RestoreOrder` 110）。保存するのは次の4つ。

- 起きた固定イベントの記録
- 今月の抽選済みの印と、予約済みの発生日
- 直前に出した悪い・良いイベントのid
- 発生率の補正（食事の補正など）

出番待ちのダイアログは保存しない（ロードで捨てる）。

### 未実装・未決定

- 固定イベントの文面の主語「みらい」は、アセットに直接書いてある。プレイヤーが名前を決められるようにするときに1か所から参照する形へ直す。
- 6歳以降の固定イベント（入学・卒業・健康診断・七五三など）。
