# イベント一覧

> メリット（子育てを優位にする）とデメリット（風邪など）の両方。**効果はすべてたたき台。**
> 発生方法は「ランダム抽選＋条件（年齢・お金・体調・季節など）で確率が変動」を想定（**発生ロジックは未確定**）。
> 制度そのものの詳細・自己負担は [support-systems.md](support-systems.md) を参照。

---

## 1. メリットイベント

### 政府の制度
| イベント | 発生条件 | 効果 |
|---|---|---|
| 児童手当 | 毎月（年齢で額変動） | お金 +（子が中学生まで） |
| 出産育児一時金 | 出産時 | お金 +（まとまった額） |
| 幼児教育・保育の無償化 | 子が3〜5歳 | 保育料の支出が0に |
| 医療費助成 | 通院・入院イベント時 | 医療費の支出を軽減 |
| 児童扶養手当 | 特定の家庭状況 | お金 + |

### 自治体の制度
| イベント | 発生条件 | 効果 |
|---|---|---|
| 子育て支援センター | 申込 | 親ストレス −、相談で不安解消 |
| 一時預かり保育 | 申込 | 親の時間確保 → 仕事とストレスを両立しやすく |
| 学童保育 | 子が小学生 | 親がワーク寄りでも子を放置しない（成績維持） |
| 予防接種の補助 | 定期 | 体調低下イベントの発生率ダウン |
| 給食費・教材費の補助 | 就学中 | 支出減 |
| 図書館・地域イベント | 不定期 | 子の成績 or 趣味 + |

### 便利なアプリ / サービス
| イベント | 発生条件 | 効果 |
|---|---|---|
| オンライン学習アプリ | 導入（課金） | 子の成績 +（毎月わずかな支出） |
| 家計簿アプリ | 導入 | 支出が見える化、無駄遣いイベント減 |
| フリマアプリ | 不用品発生時 | お金 +（不要になったベビー用品など） |
| 時短家電・デリバリー | 導入（支出） | 親の時間 + → ストレス − |
| 育児記録・見守りアプリ | 導入 | 体調異変の早期発見（重症化を防ぐ） |

## 2. デメリットイベント

| イベント | 発生条件 | 効果 |
|---|---|---|
| 風邪・インフルエンザ | ランダム（冬に確率↑、予防接種で↓） | 子の体調 −、医療費、看病で親ストレス +・仕事欠勤（月給 −） |
| ケガ・骨折 | ランダム（活発な子で↑） | 体調 −、医療費、趣味（スポーツ）一時停止 |
| 虫歯・アレルギー | 食事の質が低い月が続くと↑ | 体調 −、通院の支出 |
| 保育園からの呼び出し | 就園中ランダム | 仕事中断（ワーク寄りだと月給ダメージ大） |
| イヤイヤ期・反抗期 | 特定の年齢帯 | 親ストレス +、対応の選択肢イベント |
| 待機児童（入園できない） | 都市部設定・年度替わり | 親が仕事をセーブせざるを得ない（月給 −） |
| 家電の故障・急な出費 | ランダム | お金 −（家計簿アプリがあれば軽減余地） |
| 物価高・値上げ | 不定期 | 食事など支出が一時的に増加 |
| 学校でのトラブル | 就学中ランダム | 子のメンタル/成績 −、対応イベント |

## 3. 行動選択

イベントが発生したらカードで提示し、プレイヤーが行動を選ぶ。**選択画面を開いている間はゲーム内時間を止める**（[../decisions/0004-pause-during-decisions.md](../decisions/0004-pause-during-decisions.md)）。効果を読み比べている間に日が進むと、比べること自体が罰になるため。

### カードの構成

```
[メリット / デメリット のラベル]
 アイコン
 タイトル          例：「みらいが風邪をひいた」
 ひとこと説明       例：「熱があるみたい。病院で診てもらう？ それとも家で様子を見る？」
 効果チップ         例：体調 −15 ／ ストレス +8
 選択肢ボタン ×2    例：「病院に行く（医療費 8,000円・助成適用前）」／「家で様子を見る」
```

- **選択肢は2つを基本**にする。読んで比べられる量に収める。
- 効果チップは `Effect` のリストから自動生成する。手書きしない。→ [effects.md](effects.md) 5章
- ストレスは人ごとに持つので、チップは対象が分かる形で出す（「親ストレス −10」「子ストレス −5」）。全員に同じ量が入るときだけ「ストレス −5」にまとめる。→ [../decisions/0005-per-person-stress.md](../decisions/0005-per-person-stress.md)

### 選択肢のデータ

**各イベントは選択肢を持ち、選択肢は `List<Effect>` を持つだけ。** イベント側で `GameState` を直接叩かない。→ [effects.md](effects.md)

```
イベント「みらいが風邪をひいた」
├ 選択肢「病院に行く」      : [ Money -8000（保険診療の自己負担）, Health +15 → Child ]、insuredMedicalExpense = true
└ 選択肢「家で様子を見る」  : [ Stress +8 → Child, BadEventRate +5% (Days 7) ]
```

こうしておけば、後から「成績が下がる」「趣味が一時停止する」といった効果を**選択肢のデータに足すだけ**で増やせる。数値も効果も今後変わる前提なので、ここは守ること。

`EventChoice.insuredMedicalExpense` が true の選択肢では、負の Money 効果を保険診療の自己負担として扱う。子ども医療費助成が申請済みかつ対象年齢なら助成後の支払額と助成額を家計簿に記録する。保険適用外の費用にはこのフラグを付けない。既存の「病院に行く」選択肢には設定済み。

> 子どもの名前は「みらい」。イベント文面で名前を使うときは、ハードコードせず1箇所から参照できるようにしておく（将来プレイヤーが名前を決められるようにする余地を残すため）。

## 4. 設計メモ

- **メリットとデメリットは連動させると深みが出る**：
  - 例）予防接種の補助（メリット）を受けておくと、風邪イベント（デメリット）の確率が下がる。
  - 例）一時預かり保育（メリット）があると、保育園の呼び出し（デメリット）のダメージを減らせる。
- **「知っていれば得をする」構造**が、この企画のテーマ（制度・アプリを知る）と噛み合う。
  - 制度を知らずに見逃す／申請して活用する、という選択で差が出るようにする。
- 発生確率は 年齢・季節・お金・体調・過去の選択 で変動させ、毎回違う展開に。
