# 支出の仕組み（家計簿）

> 毎月かかるお金（家賃・光熱費・保育料・学費・塾など）をデータで持ち、月が変わるたびに引き落とす仕組み。
> **目的は「子育てにどれだけお金がかかるか」をプレイヤーが体感すること**（2026-10-05 決定）。金額は実際の円。下の表の金額は公的な調査の平均や目安で、**ゲームに入れる前に調整するたたき台**。

---

> **2026-10-09**：どんな費目（電気代・税金など）を入れるかは、他のメンバーに現実の支出を調べてもらってから決めて実装する。6章の表はそれまでのたたき台。

## 1. 何が変わるか

今のお金の動き：給料（月1回）＋ 食事・イベント・制度の Effect。
足すもの：**毎月の決まった支出**と、**支援制度による肩代わり**、それを見せる**家計簿**。

```
月が変わる（MonthTicker.OnMonthChanged）
  ├ 給料が入る（HouseholdIncome・実装済み）
  ├ ExpenseManager：今月かかる支出を全部計算
  │     支出項目（ExpenseItem）×「今の年齢・条件・プレイヤーの選択」→ 今月の額
  │     − 支援制度の肩代わり（SupportScheme.covers）
  │     → EffectApplier で Money を減らす
  └ Ledger（家計簿）に1行ずつ記録 → 家計簿画面・年間のまとめで見せる
```

- **お金を減らすのは `EffectApplier` だけ**（AGENTS.md ルール3）。`ExpenseManager` は「いくら引くか」を決めて Effect を作り、渡すだけ。
- 支出の「条件」は支援制度と同じ部品（`RequirementSO` / `GameContext`、[support-apply.md](support-apply.md) 4章）を使う。

---

## 2. 支出の種類

| 種類 | プレイヤーの操作 | 例 |
|---|---|---|
| **生活の固定費** | なし（自動） | 家賃、電気・ガス・水道、通信 |
| **子どもの段階でかかるもの** | なし（年齢で自動） | 保育料（0〜5歳）、学校教育費・給食費（小・中・高） |
| **選んで払うもの** | 申し込む／やめる | 学習塾、習い事 |
| **食費** | 食事のランクを選ぶ（有坂さん） | 最安値／普通／高級 |
| **その時だけ** | イベントで発生（丸山さん） | 病院代、修学旅行 |

食費とイベントの支出はそれぞれの機能が Effect で減らす。家計簿に載せるため、記録の仕方だけ揃える（5章）。

## 3. データ

### 3.1 支出項目（ExpenseItem・アセット1つ＝支出1つ）

```csharp
public enum ExpenseCategory { 住居, 光熱費, 通信, 食費, 保育, 学校, 塾習い事, 医療, その他 }
public enum ExpenseMode     { Auto, Optional }   // 自動でかかる／プレイヤーが申し込んだらかかる

[System.Serializable]
public class CostTier                 // 支援制度の PaymentTier と同じ考え方の「年齢の段」
{
    public string  label;             // 例 "0〜2歳"
    public GameDay fromAge;           // この日から（含む）
    public GameDay toAge;             // この日まで（含む）
    public int     monthlyCost;       // この段の毎月の額（円）
    public List<RequirementSO> requirements;   // 例：年収○円以下（保育料の所得段階）
    public List<Effect> monthlyEffects;        // お金以外の毎月の効果（塾：成績+、子ストレス+）
}

[CreateAssetMenu(menuName = "子育て/支出項目")]
public class ExpenseItem : ScriptableObject
{
    public string id;                 // 例 "nursery_fee"（セーブ・制度の covers が参照。後から変えない）
    public string title;              // 例 "保育料"
    [TextArea] public string description;
    public ExpenseCategory category;
    public ExpenseMode mode = ExpenseMode.Auto;
    public List<CostTier> tiers;      // 上から順に「年齢が範囲内 かつ 条件を全部満たす」最初の段を使う
}
```

- 段の選び方は支援制度の支給表（support-apply.md 3.2）と同じ。**当てはまる段がなければその月は 0 円**。
- 所得で額が変わるもの（保育料）は、同じ年齢の段を年収の条件つきで並べる（安い順に上から）。

## 4. 支援制度による肩代わり（無償化）

**無償化はお金を配るのではなく、支出を減らす**（2026-10-05 決定）。支援制度に「どの支出を、どれだけ肩代わりするか」を持たせる。

```csharp
public enum CoverType { Full, Rate, UpTo }   // 全額／割合／○円まで

[System.Serializable]
public class ExpenseCover
{
    public ExpenseItem expense;   // 肩代わりする支出（例：保育料）
    public CoverType   type = CoverType.Full;
    public float       value;     // Rate なら 0〜1、UpTo なら円
    public GameDay     fromAge;   // この期間だけ（例：3歳〜5歳）
    public GameDay     toAge;
}
```

- 毎月の計算：`支払う額 = 支出の額 − 受給中の制度の肩代わり合計`（0 未満にはしない）。
- **肩代わりは制度が「受給中」のときだけ**。申請しなければ全額払う＝「知っていれば得をする」。
- 対象外のものは残る（例：無償化でも給食費は払う）→ 現実の「無償化なのにお金がかかる」が体験できる。

## 5. 家計簿（Ledger）

毎月の「入ってきたお金・出ていったお金・支援で助かったお金」を記録して見せる。**学習目的の中心**。

```csharp
[System.Serializable]
public class LedgerLine
{
    public int    monthIndex;     // 歳*12 + (月-1)
    public string source;         // 例 "保育料" "給料（母）" "児童手当" "食費（普通）" "病院代"
    public ExpenseCategory category;
    public int    amount;         // 入金 +／出金 −
    public int    covered;        // 支援で肩代わりされた額（0 なら空欄）
}
```

- 記録は `Ledger.Record(...)`（Core）の1か所。給料・支出・制度の支給は Core 側で記録する。
- **食費（有坂さん）とイベント（丸山さん）のお金も家計簿に載せたい**ので、どちらかにする（要相談）：
  - 案A：`EffectApplier.Apply(effects, source)` のように「何のお金か」を渡せる形を足し、`EffectApplier` が Money のときに `Ledger.Record` する。各機能は呼び方を1つ変えるだけ。
  - 案B：各機能が `Ledger.Record` を自分で呼ぶ。
  - → 記録漏れが起きにくい**案A**を提案。
- 直近24か月ぶんを持つ（セーブ対象）。年間の合計は別に持つ（誕生日のまとめ用）。

### 5.1 見せ方（たたき台）

1. **月の家計簿**：ステータスパネルか下部ボタンから開く。今月と先月の「収入／支出（カテゴリ別）／支援で助かった額／差し引き」。
2. **誕生日のまとめ**：子どもが1歳になるたびに「この1年でかかったお金：○○円（うち支援 ○○円）」を出す（時間を止める）。
3. **最後のまとめ**：20歳のエンディングで「子育てにかかった合計」と、全国の平均（文科省・内閣府の調査）を並べて見せる。

## 5.5 給料は手取りで入る（2026-10-06 決定）

現実の給料は、額面から**税金（所得税・住民税）と社会保険料（健康保険・年金・雇用保険）**が引かれて振り込まれる。学習目的のため、ゲームでも**手取りでお金が増える**ようにする。

- 給料日（`HouseholdIncome.Payday`）に、額面 × **手取り率** を所持金に足す。
- 手取り率は **0.8**（たたき台）。現実の目安は年収や家族構成で 75〜85%。Inspector で変えられるようにする（`HouseholdIncome` に `[Range(0.5f,1f)] takeHomeRate`）。
- **給料日に「給料が入りました（手取り +○○円）」の通知を1つだけ出す**（2026-10-07 決定）。支援制度の毎月の支給は個別に通知しない。
- 家計簿には「給料（母）額面 +250,000」「税金・社会保険 −50,000」のように**引かれた額も1行で見せる**（何に引かれているかを知ることが学習になる）。
- 申請条件の「年収」は**額面**で数える（[support-apply.md](support-apply.md) 4.2.1。現実の所得制限の目安も額面の年収で語られることが多いため）。`IncomeHistory` には額面を記録する。
- 将来、年収で手取り率を変える（累進）ことも段の表でできるが、今は一律。
- **ボーナスは入れない**（2026-10-07 決定）。お金が増える仕組みはイベントや頑張りを優先する。

## 5.6 家計簿への載せ方（今のコードとの関係）

**家計簿（`Ledger`）はまだ作っていない。この文書で設計しただけ。** 作るのは山口（支出の担当）。

家計簿は「お金がいつ・何のために動いたか」を1行ずつ記録する。ところが今のコードでは、お金が動く場所が3つあり、どれも「何のお金か」を言わずに `GameState.AddMoney` まで届いている。

| お金が動く場所 | 今のコード | 家計簿に載せるためにやること |
|---|---|---|
| 給料 | `HouseholdIncome.Payday` → `GameState.I.AddMoney(income)` | 山口が自分で `Ledger.Record` を足す（Core 内で完結） |
| イベントの選択肢（丸山さん・実装済み） | `EventChoiceButtonUI` 56行目 → `EffectApplier.Apply(currentChoice.effects)` | 下の案A なら **この1行に「何のお金か」を足すだけ** |
| 食事（有坂さん・未実装） | まだない | 作るときに最初から案A の書き方で呼んでもらう |
| 支出・支援制度（山口） | これから作る | 山口が案A の書き方で呼ぶ |

**案A（提案）：`EffectApplier` に「何のお金か」を渡せる形を足す**

```csharp
// 今の呼び方（そのまま使える。家計簿には「その他」として載る）
EffectApplier.Apply(effects);

// 足す呼び方
EffectApplier.Apply(effects, new LedgerSource("病院に連れて行く", ExpenseCategory.医療));
```

- `EffectApplier` は Money の効果を適用するとき、`Ledger.Record` も呼ぶ。**お金が動けば必ず家計簿に残る**ので記録漏れが起きない。
- 丸山さんの変更は `EventChoiceButtonUI` の1行（イベント名と選択肢名を渡す）。古い呼び方も残すので、すぐ直さなくても壊れない。
- **案A に決定、変更は丸山さんに依頼する（2026-10-06）。** `EffectApplier` は丸山さんのフォルダ（`Assets/Maruyama/Scripts/Core/`）にあるため。
  - 丸山さんの作業：①`EffectApplier.Apply(effects, LedgerSource source)` の呼び方を追加（今の `Apply(effects)` は残す）。Money の効果を適用したら `Ledger.Record` を呼ぶ ②`EventChoiceButtonUI` 56行目でイベント名・選択肢名を渡す。
  - 山口の作業（先に用意）：`LedgerSource`（文字列＋`ExpenseCategory`）と `Ledger.Record` を Core に作る。これが無いと丸山さんの変更がコンパイルできないので、**山口 → 丸山さんの順**。

## 5.7 お金が足りなくなったとき（2026-10-06 方針）

### 今の状態

- `GameState.AddMoney` は `Mathf.Max(0, …)` で **0 円より下にならない**。だから今は支出を払えなくても 0 円で止まり、何も起きない。
- 家出のゲームオーバーは `RunawayWatcher`（子ストレスが限界のまま規定日数続いたら家出）で実装済み。**同じ形でお金版を作れる**。

### 2つの案の比較（残り数日で作れるか）

| | 案1：ゲームオーバー（猶予つき） | 案2：借金・返済・支援を受けて生活 |
|---|---|---|
| やること | ①`AddMoney` の 0 止めを外す ②`BankruptcyWatcher`（`RunawayWatcher` を真似る）③破綻の画面 | 案1 ＋ 借入の状態（残高・利息・毎月の返済）、借りる画面、返済の家計簿行、生活保護などの支援制度と条件、セーブ |
| 新しく作る部品 | 1〜2個 | 5〜7個 |
| 目安 | **半日〜1日** | **3〜5日**（バランス調整を含むともっと） |
| 危ないところ | ほぼない | 利息と返済のバランスが崩れると「借りれば得」「借りたら詰む」になりやすい |

→ **案1を採用（2026-10-06 決定）。案2は猶予期間中の支援金・借金として後から追加する。** 案1の部品はそのまま案2の土台になる（「赤字の月数を数える」部分が借金の判定に使える）。

### 案1の仕様（猶予つきゲームオーバー）

- `GameState.AddMoney` の **0 円止めを外す**（マイナスを許す）。HUD はマイナスを赤字で表示。
- 月の精算（給料と支出）が終わった時点で所持金がマイナスなら「**赤字の月**」を1つ数える。プラスに戻れば 0 に戻す。
- 赤字の月ごとに**時間を止めて警告**を出す：「今月は ○○円 足りませんでした（来月も赤字だと家計が破綻します）」。家計簿を開くボタンと、申請できる支援制度があればサポート画面へのボタンを出す（＝「支援を知っていれば助かる」の学習につながる）。
- **赤字が2か月続いたら家計破綻でゲームオーバー**（2026-10-06 決定）。0円を少し下回っただけではすぐ終わらない（2か月の猶予）。
- 猶予期間中に使える支援金・借金の制度は、ゲームオーバーまわりが動いてから追加する（決定）。最後の画面に「何にお金がかかっていたか」（家計簿の直近2か月のカテゴリ別）を出す。
- 作り方は `RunawayWatcher` と同じ：`BankruptcyWatcher`（Core）が `OnDeficitMonthsChanged(int)`／`OnBankrupt` を出し、`GameClock` を止める。

### 注意：今の `OnGameOver` は「ゴール到達」で呼ばれている

`GameState.OnGameOver` は今、**20歳に到達したとき**に発火している（ゴール＝クリア）。家出・家計破綻も同じ名前で呼ぶと区別できないので、終わり方の理由を持たせる。

```csharp
public enum GameEndReason { GoalReached, Runaway, Bankrupt }
public event Action<GameEndReason> OnGameEnded;   // OnGameOver の代わり（移行期間は両方出す）
public void EndGame(GameEndReason reason);
```
