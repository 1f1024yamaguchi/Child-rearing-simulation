# イベントの編集ウィンドウとストーリー分岐（設計・2026-11-11）

> チュートリアル・支援制度の編集ウィンドウと同じ作りで、メリット／デメリットイベントを簡単に作れるようにする。
> あわせて「前に選んだ選択肢でその後の展開が変わる」ストーリーの土台を作る。
> 数値・レイアウトの寸法はすべてたたき台。**スクリプトは Antigravity に段階ごとに依頼する**（このドキュメントは設計だけ）。
> 依頼文：[../team/antigravity-event-editor.md](../team/antigravity-event-editor.md)　ストーリーの管理ツール：[story-tool.md](story-tool.md)
> リポジトリでは `docs/design/event-editor.md` に置く。

## 0. いまのコードで確認したこと（2026-11-11 時点）

| やりたいこと | いまの状態 | 足りないところ |
|---|---|---|
| 画像を入れたり入れなかったり | `EventData.iconSprite` は空でもよく、空なら `EventCardUI` がアイコンを隠す | カードの配置が固定（Icon 80×80・Title・Description 400×70 の位置が決まっている）ので、**画像が無いと穴が空くだけ**で文章が広がらない |
| 選択肢を増やしたり減らしたり | `EventData.choices` はリストで、カードは数だけ `ChoiceBlock` を作る（**データは何個でも持てる**） | `ChoicesContainer` の高さが 200、`ChoiceBlock` が 90＋間隔12 → **2つまでしか入らない**。3つ目ははみ出る。events.md 3章にも「選択肢は2つを基本」とある |
| 年月日を細かく決める | 固定イベント（`trigger = Fixed`）は「月・日」＋「何歳〜何歳」を持つ。抽選イベントの条件は **年齢（歳単位）とストレス段階** の2種類だけ | 「○歳○月○日〜○歳○月○日」「冬だけ」「お金が○円以下」などの条件の部品が無い。入力も Inspector の数字3つ |
| 選択でストーリーが変わる | 選んだ選択肢は `EffectApplier.Apply` に効果を渡すだけで、**どこにも記録されない** | 「何を選んだか」の記録・フラグ・それを見る条件・続きのイベント、が全部無い |
| 前の選択で出る／出ない | 条件は `EventConditionSO` の部品（足せる作り） | 部品を足せば乗る。部品が別アセットなので、作るたびにアセットが増えるのはつらい |

その他：
- 条件のアセットは `Assets/Maruyama/Data/Conditions/` に1つずつ置く方式（`Cond_Age_0to5` など）。
- イベントは `Resources/Events` に置けば `EventManager` が自動で読み込む（登録の手間は無い）。外に置くと読み込まれない。
- 1日に1枚ずつ（悪い1・良い1の組）を順番待ちで出す仕組み（`pendingDialogs`）はすでにある。

## 1. 全体の形

```
[編集ウィンドウ]（Editor）── イベントを作る・条件を付ける・選択肢を並べる・つながりを見る
        │ 書くのは今までどおり EventData アセット
        ▼
[EventData]（丸山さん）── 出方・条件・選択肢（＋選択肢の ID と「ストーリーの効果」）
        │ 選んだら
        ▼
[ストーリーの記録 StoryState]（新規・Core）── 選んだ選択肢の履歴・フラグ・予約中の続き
        │ 読む                         │ 予約日が来たら
        ▼                              ▼
[条件の部品]（新規）            [StoryEventScheduler]（新規）→ EventManager.Enqueue
 前の選択・フラグ・日付・月・お金…   続きのイベント／条件を満たしたら1回
        │ 同じ仕組みを使う
        ▼
 チュートリアル（フラグで出す・ページの出し分け）／職業の判定（フラグを条件に）
```

**方針**
- ストーリーの効果（フラグを立てる・趣味を決める・続きを予約する…）は、**選択肢の `List<Effect>` に効果の種類として足す**。events.md 3章の「選択肢は効果のリストを持つだけ」を崩さない。
- 「何を選んだか」は**自動で記録**する。単純な分岐（イベントAで「はい」を選んだら B が出る）はフラグを作らなくても書ける。
- フラグは文字列ではなく**アセット（StoryFlag）**にする。打ち間違いで黙って効かなくなるのを防ぎ、編集ウィンドウで「どこで立てて、どこで使っているか」を逆引きできるようにする。

## 2. カードの見た目（画像のあり・なし／選択肢 1〜4）

### 2.1 画像
- 画像あり：今と同じ（上にドット絵）。
- 画像なし：画像の枠ごと消し、**タイトルと説明文が上に詰まって、説明文の高さが広がる**。
- やり方：カードの中身（画像・タイトル・説明・選択肢）を `VerticalLayoutGroup` に入れ、画像の GameObject を `SetActive(false)` するだけで詰まるようにする。説明文は `LayoutElement.flexibleHeight` で余りを使う。
- 画像はドット絵（チュートリアルと同じく、未設定のあいだは差し替え枠＋「絵の指示メモ」を出せるとよい → 編集ウィンドウの欄に「絵の指示メモ」を持たせる）。

### 2.2 選択肢の数（2026-11-11 決定：最大4つ、4つは 2×2）
- **1〜4つ**にする（5つ以上は編集ウィンドウで ✕）。基本は2つのまま、必要なときだけ1・3・4（events.md 3章の「2つを基本」は「2つを基本、最大4つ」に書き換える）。
- **イベントの画面は大きくしてよい**（決定）。カード・ダイアログの寸法は Unity で並べて決める（人間が確認）。
- 並べ方：

| 数 | 並べ方 |
|---|---|
| 1〜3 | 縦に1列（今と同じ）。`VerticalLayoutGroup` |
| 4 | **2×2**（決定）。`GridLayoutGroup`（2列）。1つの幅はカードの半分、チップは1行に詰める |

- `ChoicesContainer` に `ContentSizeFitter` を付け、数に合わせて伸ばす。数で `VerticalLayoutGroup` と `GridLayoutGroup` を切り替える（両方の箱をプレハブに用意して、使うほうだけ表示する形でもよい）。
- 2×2 のときはボタンの文字が長いと入らないので、編集ウィンドウで「4つのときはラベル○文字以内」を ⚠ にする（文字数はたたき台）。

### 2.3 選択肢ごとの「出す条件」（あると便利・段階3）
- 選択肢に条件を付けられるようにする（例：お金が5万円以上のときだけ「習い事に通わせる」を押せる）。
- 満たさない選択肢は**消さずに灰色で押せなくし、理由を小さく出す**（「お金が足りない」）。何があったかが分かるほうが学びになるため。
- 全部の選択肢が押せない状態は ✕（編集ウィンドウのチェックで警告）。

## 3. いつ出るか（出方と条件）

### 3.1 出方（`EventTrigger`）を5つにする

| 出方 | 内容 | いま |
|---|---|---|
| 抽選 | 月ごとの抽選で当たった日に、条件を満たすものから重みで選ぶ | ある |
| 決まった日 | 「○歳○月○日に1回」または「毎年○月○日（○歳〜○歳）」に必ず | ある（入力を年月日にするだけ） |
| **続き** | 別のイベントの選択肢から「○日後に出す」と予約されたときだけ出る。抽選には入らない | 新規 |
| **条件を満たしたら** | 条件を満たした最初の日に1回だけ出る（チュートリアルと同じ考え方） | 新規 |
| （コードから） | コードから呼んだときだけ | 新規・おまけ |

- 「続き」「条件を満たしたら」は抽選の候補に入れない（`EventManager.AddToPool` で除く）。判定と予約は `StoryEventScheduler` が持ち、出すときは `EventManager.Enqueue(EventData)` で順番待ちに入れる。
- 「抽選」にも **「一生に1回だけ」** のチェックを付ける（いまは `cooldownDays` しか無い）。中身は「このイベントがまだ起きていない」という条件（3.2）を自動で付けるだけ。

### 3.2 条件の部品（足すもの）

すべて「すべて満たしたら」（AND）。「どれか1つ」（OR）は、必要になったら「どれかを満たす」部品を1つ足して入れ子にする。

| 部品 | 内容 | 例 |
|---|---|---|
| 年齢の範囲（既存） | 満年齢 ○〜○歳 | 0〜5歳 |
| **日付の範囲** | ○歳○月○日 〜 ○歳○月○日（`GameDay` 2つ） | 6歳4月1日〜6歳7月31日（小1の1学期） |
| **月** | 1〜12月のチェック | 12・1・2月（冬だけ） |
| **学年** | 年少〜高3・大学 の範囲（ending.md の「学年と月」と同じ区切り） | 小3〜小6 |
| ストレス段階（既存） | 子・母・父・親の平均 | 子が危険以上 |
| **子どもの値** | 成績・体調・趣味Lv が ○以上／以下、趣味の種類が ○ | 趣味がスポーツ・Lv3以上 |
| **お金** | 所持金が ○円以上／以下 | 10万円以下 |
| **前の選択** | イベントX が「起きた／起きていない」、X で選択肢Y を「選んだ／選ばなかった」 | 野球教室で「通わせる」を選んだ |
| **フラグ** | StoryFlag が「立っている／立っていない」 | 野球をやっている |
| **支援制度** | 制度Xを「受給中／受けていない」 | 予防接種の補助を受けていない |
| **支援の条件を流用** | 支援制度の `RequirementSO`（世帯年収など）をそのまま使う薄い入れ物 | 年収400万円以下 |
| 特性・状態 | 家族のだれかが特性X／状態Y を持っている | 子が「風邪気味」 |

- 部品はすべて `EventConditionSO` を継承する（丸山さんの基底クラスはそのまま）。新しい部品は `Assets/Yamaguchi/Scripts/Story/Conditions/` に置く。
- 各部品に `Describe()`（「6歳4月1日〜6歳7月31日」「冬（12・1・2月）」）を持たせ、編集ウィンドウのまとめ文に使う。
- **条件アセットが増えすぎないように**：編集ウィンドウで「新しく作る」で作った条件は、**イベントのアセットの中（サブアセット）に保存**する（`AssetDatabase.AddObjectToAsset`）。データの形は変わらない（参照先がイベントの中にあるだけ）。共通で使いたい条件（`Cond_Age_0to5` など）は今までどおり別アセットで選べる。

## 4. ストーリー分岐の仕組み

### 4.1 記録するもの（`StoryState`・セーブキー `"story"`）

| 記録 | 中身 | 付く時 |
|---|---|---|
| 起きたイベント | イベントID → 回数・最後に起きた日 | カードが出たとき |
| 選んだ選択肢 | イベントID → 選んだ選択肢ID（最後のもの）と日 | 選択肢を押したとき（自動） |
| フラグ | 立っている StoryFlag の ID の集合 | 効果「フラグを立てる／消す」 |
| 予約中の続き | イベントID と出る日 | 効果「続きを予約」 |

- 選択肢には**ID**を持たせる（並べ替えても記録がずれないように。番号では持たない）。編集ウィンドウが自動で付ける（`go` `stay` のように変えてもよい）。
- 記録は `LifeRecorder` の「できごとの記録」にも流せる（振り返りで「7歳 野球教室に通い始めた」）。ending.md の未決定「EventManager に『イベントを選び終えた』通知を足してもらう」も、この通知で片付く。

### 4.2 選択肢に足す効果（`EffectKind` に足す）

| 種類 | 対象・中身 | 例 |
|---|---|---|
| `SetFlag` / `ClearFlag` | StoryFlag | 「野球をやっている」を立てる |
| `SetHobby` | 子・趣味の種類 | 趣味をスポーツにする |
| `AddTrait` / `AddCondition`（予約済み） | 特性・状態の定義 | 特性「野球が好き」 |
| `ScheduleEvent` | イベント・何日後 | 180日後に「初めての試合」 |
| `ShowStory` | TutorialData | 選んだ直後にストーリーの画面を出す |

- `Effect` に**参照の欄を1つ**（`UnityEngine.Object asset`）足す。フラグ・特性・イベント・チュートリアルはここに入れる。趣味の種類は今の `value` を使う。
- `AddTrait` / `AddCondition` は traits.md で予定していたもの。参照の欄ができるのでここで一緒に繋がる（antigravity-child-status.md 末尾の「ConditionSystem のループ中の変更」対策も、この段階で必ず入れる）。
- 効果チップは、ストーリーの効果は**出さない**（「フラグ」は画面に出すものではないため）。趣味・特性だけ「趣味：スポーツ」「特性：野球が好き」のチップにする（たたき台）。

### 4.3 例：野球教室 → プロ野球選手

```
「野球教室の体験会」 抽選・メリット・6〜9歳・一生に1回
├ 通わせる（月謝 −5,000）
│   SetHobby スポーツ / SetFlag 野球をやっている / 趣味 +20
│   ScheduleEvent 「初めての試合」180日後 / ShowStory 「野球を始めた」
└ 今回はやめておく          （何もしない。選んだことは自動で記録される）

「初めての試合」 続き・メリット
├ 応援に行く        親ストレス −5 / 子ストレス −10
└ 仕事で行けない    子ストレス +5 / お金 +（休まなかった分）

「少年野球の大会」 抽選・10〜12歳・条件：フラグ「野球をやっている」
「野球をやめたい」 抽選・デメリット・条件：フラグ「野球をやっている」＋子ストレス危険以上
├ 続けさせる   子ストレス +10
└ やめさせる   ClearFlag 野球をやっている

「別の習い事のさそい」 抽選・条件：前の選択「野球教室の体験会」で「今回はやめておく」を選んだ

職業「プロ野球選手」 条件：フラグ「野球をやっている」＋趣味（スポーツ）Lv ○以上 ＋ 推薦の進路
```

- 「野球」は趣味の種類（`HobbyKind`）を増やさず、**スポーツ＋フラグ**で表す（2026-11-11 決定）。種類を増やすとカード表示・成長計算・進路の判定に広く影響するため。

#### プレイヤーにはどう見えるか（「スポーツ」は内部の分類で、画面には「野球」と出す）
`StoryFlag` に **「趣味の呼び名」**（任意）を持たせる。フラグ「野球をやっている」＝ 趣味の分類スポーツ・呼び名「野球」。
フラグが立っていて、子の趣味の分類が同じとき、画面の「スポーツ」を呼び名に置き換える。

| 場所 | 表示 |
|---|---|
| 子どもカードのプロフィール | 8歳・**野球**が好き |
| ステータス欄の趣味の行 | 趣味　**野球** Lv3 |
| 効果チップ | 趣味：**野球** +20 |
| 特性の行（付けた場合） | 野球が好き　趣味+10% |
| イベントの文章 | 文面に直接書く（「少年野球の大会に出ることに！」） |
| 職業・リザルト | **プロ野球選手**になりました |
| 振り返り（できごとの記録） | 7歳　野球教室に通い始めた |

- 呼び名を持つフラグが複数立っていたら、後から立ったほうを出す（たたき台）。
- フラグが消えたら（「やめさせる」）表示は「スポーツ」に戻る。趣味Lv はそのまま。
- プレイヤーは「スポーツ」という分類を意識しない。成長計算・進路の判定は分類（スポーツ）で行う。
- 職業の条件は `RequirementSO` なので、フラグを見る `StoryFlagRequirementSO` を1つ足せば CareerDefinition から使える（支援制度の条件にも使える）。
- 習い事の月謝のような「毎月の支出」を始める効果は、家計簿（ExpenseItem）と合わせて後で考える（今回は1回の支払いだけ）。

### 4.4 ストーリーの文章（チュートリアル形式）を変える
- `TutorialTiming` に **「フラグが立った日」**（＋ずらす日数）を足す。「野球を始めた」のストーリーを、選んだ次の日に出せる。
- `TutorialPage` に **「このページを出す条件」**（任意・条件の部品をそのまま使う）を足す。条件を満たさないページは飛ばす。同じチュートリアルで、野球を選んだ子と選ばなかった子で途中のページが変わる。
- 文章に `{name}`（子どもの名前「みらい」）を書けるようにする。events.md 3章の「名前はハードコードしない」と同じ。イベントのタイトル・説明・選択肢にも使う。
- 選んだ直後に出すなら効果 `ShowStory`、日をおいて出すならチュートリアルのタイミング「フラグが立った日」、と使い分ける。

## 5. 編集ウィンドウ

メニュー：**子育て → イベント → 編集ウィンドウ**（EventData の Inspector にも「編集ウィンドウで開く」）。支援制度の編集ウィンドウと同じ並び。

```
[説明] イベント1つ＝アセット1つ。Resources/Events に置くと自動でゲームに出ます。
イベント [▢ EventData   ◎] [新しく作る ▼] [複製して作る]

── 選んだイベント ─────────────────────────────
■ まとめ（自動）
  メリット・抽選。6〜9歳。一生に1回。重み 1。
  選択肢2つ：通わせる（−5,000円・趣味スポーツ・フラグ「野球」・180日後に「初めての試合」）／今回はやめておく
■ 基本      ID（自動）/ メリット・デメリット / タイトル / 説明（{name} を挿入）
             画像 [▢ Sprite] ☐ 画像なし　絵の指示メモ
■ いつ出るか ◉抽選 ○決まった日 ○続き ○条件を満たしたら ○コードから
             （出方に合う欄だけ表示）
■ 出る条件   ＋条件を足す ▼   各条件をその場で編集・Describe の文
■ 選択肢（1〜4）  [＋選択肢] 各選択肢を折りたたみ、[↑][↓][✕]
■ ストーリーのつながり（自動・逆引き）
■ カードのプレビュー
■ チェック   ✕ 選択肢が5つ以上です / ⚠ 「初めての試合」はどこからも予約されていません …
■ 置き場所   ✓ Resources/Events にあります（自動で読み込まれます）
■ 再生中だけ

── すべてのイベント ──────────────────────────
[一覧][年表]  [メリット 9][デメリット 5][決まった日 5][続き 0][条件 0]
```

### 5.1 新しく作る ▼（テンプレート）
保存先 `Assets/Maruyama/Resources/Events/`（読み込み先を変えないため。丸山さんと要相談・6章）。ファイル名から ID を自動で付ける（`Event_Merit_Baseball` → `merit_baseball`）。

| テンプレ | 最初に入る内容 |
|---|---|
| 抽選のメリット／デメリット | 出方＝抽選、選択肢2つ（空） |
| 決まった日 | 出方＝決まった日（1回）、選択肢1つ「わかった」 |
| 続き | 出方＝続き、選択肢1つ |
| 条件を満たしたら | 出方＝条件、条件欄を開いた状態 |
| 分岐の入口（2択） | 抽選・一生に1回、選択肢2つに「続きを予約」の効果を1行ずつ |

### 5.2 いつ出るか
- **決まった日**：「◉ 1回だけ □歳[月▼][日▼]」「○ 毎年 [月▼][日▼]（□歳〜□歳）」。日はその月の日数まで（`SupportEditorGUI` の年齢入力を使い回す）。中身は今の `fixedMonth / fixedDay / fixedMinAgeYears / fixedMaxAgeYears` に書くだけなので、**データの形は変わらない**。
- **抽選**：重み・クールダウン（日 ／「1年」「半年」ボタン）・☐ 一生に1回だけ。
- **続き**：「このイベントを予約している選択肢」の一覧（逆引き）。0件なら ⚠。
- **条件を満たしたら**：☐ 一生に1回（既定 ON）。

### 5.3 出る条件
- 「＋条件を足す ▼」→ 3.2 の部品の一覧（`TypeCache.GetTypesDerivedFrom<EventConditionSO>()` で自動で並ぶ）＋「既存のアセットから選ぶ」。
- 前の選択の部品は「イベント [▼]」「選択肢 [▼]（そのイベントの選択肢のラベルが出る）」「選んだ／選ばなかった／起きた／起きていない」をドロップダウンで選ぶだけ。
- 共有の条件アセットを他のイベントも使っていたら「ほかでも使っています：○○…」＋［このイベント専用にコピー］（支援制度と同じ）。

### 5.4 選択肢
1つの選択肢の欄：
```
▼ 選択肢1  ID [go]  ラベル [通わせる]
   効果     [種類▼][対象▼][量][長さ▼]  …  [＋効果]       → チップのプレビュー：趣味 +20
   家計簿   [その他▼]  ☐ 保険診療の自己負担
   ▶ ストーリー  フラグを立てる [▢] / 消す [▢] / 趣味 [▼] / 特性 [▢] /
                 続き [▢ イベント]  [180]日後  [＋新しく作る] / ストーリーを出す [▢ Tutorial]
   ▶ 出す条件（任意）
```
- 「ストーリー」は効果のリスト（4.2）を見やすく出し分けているだけ。保存先は同じ `effects`。
- 「続き」の［＋新しく作る］で、続きのイベントを「続き」テンプレで作って即つなぐ。

### 5.5 ストーリーのつながり（逆引き・自動。全体は 5.10 のストーリーウィンドウ）
```
このイベントに来る道   ← 「野球教室の体験会」で「通わせる」（180日後）
このイベントから行く道 → 「初めての試合」（通わせる・180日後）
このイベントを条件にしているもの  「別の習い事のさそい」（今回はやめておく を選んだら）
使っているフラグ      「野球をやっている」：立てる＝ここ・「…」／見る＝「少年野球の大会」「職業：プロ野球選手」
```
行を押すとそのイベントへ移る。全体の図はストーリーウィンドウ（5.10）で見る。

### 5.6 カードのプレビュー
チュートリアルと同じく、シーンの `EventDialog`（無ければプレハブを一時的に置く）に今のイベントを表示する。画像なし・選択肢3〜4の見た目をその場で確かめるため。

### 5.7 チェック（保存はできるが目立たせる）

| 印 | 内容 |

| ✕ | ID が空・重複／タイトルが空 |
| ✕ | 選択肢が0個・5個以上／選択肢の ID が空・重複／ラベルが空 |

| ✕ | 条件・効果が参照しているイベント／選択肢／フラグが消えている |

### 5.8 一覧と年表
- **一覧**：出方のタブ、年齢順、✕・⚠ の数、選択肢の数、画像の有無。

### 5.9 再生中だけ
- 今の判定：出方・各条件の ✓✗（満たしていない条件の Describe）、クールダウンの残り。
- ［今すぐ出す］（条件を無視）／［条件を見て出す］。
- **ストーリーの状態**：立っているフラグ（付け外しできる）、選んだ選択肢の履歴、予約中の続き。
