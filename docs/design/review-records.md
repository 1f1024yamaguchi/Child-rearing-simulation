# 振り返り（成長グラフ・できごとの記録）と家庭の結末

> リザルト（[result-scene.md](result-scene.md)）に **「家庭の結末」と親の最終状態** を足し、結果発表のあとに **振り返り**（成長グラフ・家計・親・できごと）を見られるようにする。
> 振り返りはタイトル画面の「育成記録」から、終わったプレイのぶんを後から開ける。
> 進路・職業の判定は [ending.md](ending.md) が正。この文書は **プレイ中に貯める記録** と **家庭の結末の決め方** と **振り返りの画面** を決める。
> 数値・文はすべて **調整前のたたき台**。

---

## 1. 決まったこと（2026-11-09）

| 項目 | 内容 |
|---|---|
| 流れ | **結果発表 → 振り返り** の2段。巣立ち・家出・家計破綻のどれでも同じ |
| ランク・スコア | **付けない** |
| 結末の名前 | 画面にエンディング名は出さない。「○○は △△ になりました」の文だけ |
| 図鑑（コンプリート） | **作らない**。コンプリートを目指す遊びは「子育てをがんばる」という本題からずれるうえ、作るのも大変なため |
| 振り返りの入口 | end シーンの結果発表のあと、と **タイトル画面の「育成記録」** の2か所。どちらも同じ画面を使う |
| 平凡の結末 | **作らない**。どの子にも職業が付く。条件を満たす候補が無いときの既定の職業は **会社員** （ending.md 5.2） |
| 家庭の結末 | 結果発表に **家計の一文・子育ての一文・親の最終状態** を足す（3章）。母・父それぞれの一文は出さず、親ごとのことは振り返りのグラフ（ストレス・働き方）と役職の移り変わりで見せる |
| 振り返りの中身 | **成長グラフ** と **できごとの記録** を足す（4〜5章） |
| 記録の間隔 | ステータスは **毎月1回**（月の精算のあと） |
| 振り返りの形 | **縦に1本のスクロール**（タブで分けない）。家計の結末などを詳しく見られるようにする（2026-11-09 決定） |

> 決定の記録：[../decisions/0036-review-records-and-family-ending.md](../decisions/0036-review-records-and-family-ending.md)

## 2. 全体の流れ

```
プレイ中
  LifeRecorder（Main に置く）
    ├ 毎月：月の記録（MonthlySnapshot）を1件
    └ できごとが起きるたび：できごとの記録（LifeLogEntry）を1件
    ※ セーブの参加者（ISaveParticipant）。途中セーブから再開しても続く

終わったとき（result-scene.md 2章の EndingFlow）
  EndingResultBuilder が LifeRecorder の中身と Ledger の年ごとのまとめを EndingResult に写す
  家庭の結末（FamilyEndingJudge）を判定して EndingResult に入れる
  RecordStore に保存 → end シーン

end シーン
  結果発表（家庭の結末つき） → 下へスクロールすると振り返り（成長グラフ・家計・親・できごと） →［タイトルへ］

タイトル画面
  育成記録 → 一覧 → 1件を押す → 振り返り（同じ画面）
```

## 3. 家庭の結末（結果発表に足すもの）

### 3.1 画面

見た目は `end` シーン（`Assets/Yamaguchi/scenes/end.unity`）の `ResultCanvas` に、仮の値で組んである（2026-11-09。uGUI の Canvas／Screen Space - Overlay／Scale With Screen Size 800×600）。

```
  みらい は 会社員 になりました              ← 既存（職業の一文）

  ── 家族のこと ──
  毎月がぎりぎりの家計でした                  ← 家計の一文（3.2）
  好きなことを、のびのびやらせてあげた親でした  ← 子育ての一文（3.3）
  ┌ 親の最終状態 ────────────────────┐
  │     役職  月給    ストレス 働き方      │
  │ 母  課長  42万円  55       ワーク寄り  │
  │ 父  主任  30万円  30       ライフ寄り  │
  └──────────────────────────────┘
```

- **一文は「家計」と「子育て」の2つだけ。母・父それぞれの一文は出さない**（2026-11-09 決定）。親ごとのことは、振り返りの「母の20年」「父の20年」（3.4）で、グラフと役職の移り変わりとして見せる。
- 家出・家計破綻のときも出す。
- 文と数値はすべて `FamilyEndingTable`（ScriptableObject）に置き、Inspector で変えられる。

### 3.2 家計の一文（たたき台）

上から順に見て、**最初に当てはまった行** の文にする。

| # | 条件 | 文 |
|---|---|---|
| 1 | 終わり方が家計破綻 | 家計が立ち行かなくなってしまいました |
| 2 | 最終の所持金 ≤ 0 | 借金を抱えたまま、この日を迎えました |
| 3 | 赤字だった月が **3か月以上** | 毎月がぎりぎりの家計でした |
| 4 | 赤字だった月が 1〜2か月 | 赤字の月もありましたが、なんとか乗り切りました |
| 5 | 受け取った支援 ≥ 子育てにかかったお金 × **0.25** | 支援制度をうまく使って、家計を支えました |
| 6 | 最終の所持金 ≥ 子育てにかかったお金 × **0.5** | ゆとりのある家計で、子どもを育てあげました |
| 7 | それ以外 | 堅実にやりくりして、この日を迎えました |

- 赤字だった月は月の記録（4章）の所持金がマイナスだった月の数。
- 5 を 6 より上に置くのは、「制度を知って使う」がこのゲームのテーマなので、使えた人をほめたいため。

### 3.3 子育ての一文（たたき台）

「どんな親だったか」を1文で出す。月の記録から次の平均を出して、上から順に最初に当てはまった行にする。

- `b`＝子の **勉強⇔遊び** の平均（0＝勉強／1＝遊び。成績が動き出す2歳からの月だけで平均）
- `w`＝親2人の **ライフ⇔ワーク** の平均（0＝ライフ／1＝ワーク）
- `s`＝子ストレスの平均

| # | 条件 | 文 |
|---|---|---|
| 1 | 終わり方が家出 | 子どもの気持ちに、気づいてあげられませんでした |
| 2 | 子の希望と違う進路を選んだ（ending.md 3.1） | 進む道は、親が決めました |
| 3 | `s` ≥ **60** | 子どもに無理をさせてしまうこともありました |
| 4 | `b` ≥ **0.65** | 好きなことを、のびのびやらせてあげた親でした |
| 5 | `b` ≤ **0.35** | 勉強に力を入れて、しっかり支えた親でした |
| 6 | `w` ≤ **0.35** | 子どもとの時間を、たくさん作った親でした |
| 7 | `w` ≥ **0.65** | 仕事をがんばって、家計を支えた親でした |
| 8 | それ以外 | 勉強も遊びも、バランスよく見守った親でした |

- 責める言い方にしない（3・1 も「できなかったこと」をやわらかく言う）。リザルトは振り返りの場なので。

### 3.4 親の最終状態と「母の20年」「父の20年」

- 結果発表の表：終わった日の **役職・月給・ストレス・働き方**（`w` を その親だけで平均し、0.35以下＝ライフ寄り／0.65以上＝ワーク寄り／それ以外＝半々）。
- 振り返りに親ごとの欄を置く（3.1 の見た目の `sec_mother` / `sec_father`）：
  - グラフ：**ストレス** と **働き方（ライフ⇔ワーク。上ほどワーク）** の2本
  - **役職の移り変わり**：「0歳 平社員 → 8歳 主任 → 12歳 係長 → 17歳 課長」。できごとの記録の「役職が上がった」から作る
- `EndingResult` には親ごとの入れ物（`ParentResult { rank, salary, stress, workStyle }`）を持たせる（6章）。

## 3.5 end シーンの画面（仮組み・2026-11-09）

`Assets/Yamaguchi/scenes/end.unity` の `ResultCanvas` に、仮の値で見た目を組んである（スクリプトで値を入れる部分はまだ無い）。

```
┌[生まれた日]───────────────────────[巣立ちの日]┐ ← 上の四隅：画像の枠（corner_top_left / right）
│        ┌ 縦スクロール（result_scroll）──────┐        │
│        │ 結果発表（家族3人の絵・職業の一文） │        │
│        │ 家族のこと（家計の一文・子育ての一文）│        │
│        │ お金のまとめ ［家計簿で1年ずつ見る］ │        │
│        │ 子どもの最終ステータス              │        │
│        │ ── ふりかえり ──                    │        │
│        │ 子どもの成長（下に成長段階ごとの絵）│        │
│        │ 所持金・家計のまとめ［家計簿…］     │        │
│        │ 母の20年／父の20年                  │        │
│        │ できごとの記録 ［タイトルへ］       │        │
│        └──────────────────────┘        │
└──────────────────────────────────┘
```

### 家計簿を end シーンでも見られるようにする（2026-11-09 決定）

本編の家計簿で「毎年どこにお金がかかっていたか」が見られるのは学習効果が大きいので、リザルトからも開けるようにする。

- 本編と **同じプレハブ** `Prefabs/UI/LedgerPanel.prefab` を `ResultCanvas` の一番上（最後の子）に置く。最初は非表示。
- 「お金のまとめ」と「家計のまとめ」の［家計簿で1年ずつ見る］ボタンで開く。開くのは **［年］タブ**（`LedgerPanelUI.OpenYearTab()` を追加済み。最後の年が出て、‹ で0歳までさかのぼれる）。
- `Ledger` は static なので end シーンでも中身が残っている（result-scene.md 2章）。［タイトルへ］で `Ledger.I.Clear()` するので、それより前なら見られる。
- ［月］タブは Ledger が直近24か月しか行を持たないので、古い月は出ない（今の仕様のまま）。
- **タイトルの育成記録から開いたとき** は Ledger が空なので、そのままでは見られない。年ごとの行（`LinesOfYear`）を詳細ファイル（6.2）に写して、それを家計簿の画面に渡せるようにするか、育成記録ではボタンを隠すか、を決める（7章）。

### 親のグラフは「年」で書く（2026-11-09 決定）

「母の20年」「父の20年」の横軸を「0歳・6歳…」と書くと **母親の年齢** に見えるので、「**0年・6年・12年…**」と書き、見出しを「母の20年（子どもが生まれてから）」にする。役職の移り変わりも「はじめ 平社員 → 8年目 主任 → …」と書く。子どものグラフとできごとの記録は子どもの年齢なので「歳」のまま。

### 画像を入れる場所（2026-11-09 決定）

見た目が淡々としないよう、画像の枠を増やす。**キャラを歩かせる帯は作らない**（いったん作ったが、気が散るのでやめた。2026-11-09）。立ち絵は2枚の絵をゆっくりめくるだけにする。

| 場所 | 名前 | 今入れている絵（仮） |
|---|---|---|
| 上の左右の隅（固定） | `corner_top_left` / `corner_top_right` | 赤ちゃん（生まれた日）／大人になった子（巣立ちの日） |
| 結果発表 | `hero/illustration` | 母・子・父の立ち絵（職業のイラストができたら差し替え） |
| 各欄の見出しの右 | `sec_*/head/icon` | 家族・子・母・父の立ち絵。絵が無い欄は薄い灰色の枠だけ |
| 子どもの成長グラフの下 | `sec_graph_child/plot/stage_0〜4` | 赤ちゃん→幼児→小学生→中高生→大人 を、その年齢の位置に並べる |

- キャラの絵は本編の `Images_animation/Characters` の2枚1組（_0／_1）を使う。本編の Animator は SpriteRenderer 用で UI では使えないので、`UI/Result/UISpriteFlipbook.cs`（Image の絵を順番に入れ替える。`unscaledDeltaTime` で動く）でめくる。
- 本番では、子どもの絵は **終わったときの成長段階**（家出なら中高生など）、親の服は本編の `ParentOutfitSwitcher` と同じ決め方にする。

### グラフは画面に入ったら描いていく（2026-11-09 決定）

スクロールでグラフの枠が6割見えたら、線を左から右へ約1.4秒で描く（最初は速く、最後はゆっくり）。目盛りと文字は最初から出しておく。

- `UI/Result/GraphReveal.cs`：グラフの枠（`plot`）に付ける。線は `plot/lines`（RectMask2D）の中に入れ、その幅を 0 → 全幅に広げて見せる
- 子どもの成長グラフの下の絵（`stage_0〜4`）は、線がその年齢まで来たら「ぽんっ」と出す（`popItems`）
- 1回描いたら、スクロールで戻っても描き直さない。確認用に右クリック「もう一度描く」
- 本番の `LineGraphUI` に作り替えても、`lines` の入れ物に線を描けばこの部品はそのまま使える

### 子どもと親を見分けやすくする（2026-11-09 決定）

大人になった子と父の絵がほぼ同じだったので、次のように変えた。

- **父にあごひげ**：`Images_animation/Characters/Father/` の全26枚に、口の下のあごのラインへひげの点を足した（本編の父も変わる）。
- **リザルトの子どもは職業の服**：巣立ちのときは、その職業の服を着た絵を出す。今は会社員のスーツだけ作った（`Child/child_adult_suit_idle_*`・`_walk_*`。ひげの無い元の父のスーツ姿と同じ絵）。
  - 職業ごとの服・イラストは後で作る。`CareerDefinition` に「リザルトの立ち絵（2枚）」の欄を持たせ、無い職業は普段着（`child_adult_*`）にする。

## 4. 月の記録（成長グラフの元）

### 4.1 中身

`MonthTicker.OnMonthSettled`（月の精算のあと）で1件足す。

| 項目 | 内容 | 取得元 |
|---|---|---|
| `ageDays` | その日の年齢（日数） | GameState.AgeDays |
| `grade` | 成績（**2歳前は -1**。グラフでは線を引かない） | ChildStatus.Grade / IsGradeActive |
| `childStress` | 子ストレス | ChildStatus.Stress |
| `health` | 体調 | ChildStatus.Health |
| `hobbyLevel` | 趣味の熟練度 | ChildStatus.HobbyLevel |
| `money` | 所持金（マイナスあり） | GameState.Money |
| `motherStress` / `fatherStress` | 親のストレス | Household の母・父 |
| `motherBalance` / `fatherBalance` | 親のライフ⇔ワーク（0〜1） | Household の母・父 |
| `studyPlay` | 子の勉強⇔遊び（0〜1） | ChildStatus.StudyPlayBalance |

- 22歳＋浪人・留年でも 300件ほど。1件は数十バイトなので間引かない。
- 値は **丸めた整数**（画面に出ている値）で持つ。バランスだけ 0〜100 の整数にして持つ。

### 4.2 グラフ

| グラフ | 線 | 縦軸 |
|---|---|---|
| 子どもの成長 | 成績・ストレス・体調 | 0〜100 |
| お金 | 所持金 | 金額（0 の線を引く。マイナスは赤く塗る） |
| 母の20年／父の20年（親ごとに1つ） | その親のストレス・働き方（ライフ⇔ワーク） | 0〜100 |

- 横軸は年齢。目盛りは「0歳・6歳（小学校）・12歳（中学校）・15歳（高校）・18歳」に縦線を引くと、時期と結びつけやすい。
- グラフの部品は1つ（`LineGraphUI`）にして3か所で使う。uGUI の `Graphic` を継承し、`OnPopulateMesh` で折れ線を描く（外部パッケージは入れない）。

## 5. できごとの記録

### 5.1 中身

| 項目 | 内容 |
|---|---|
| `ageDays` | 起きた日の年齢（日数） |
| `kind` | 種類（下の表の enum `LifeLogKind`） |
| `who` | 対象（母／父／子／家族） |
| `text` | **記録した時点で作った表示用の文**（例「風邪をひいた」「児童手当を受け取り始めた」） |
| `amount` | お金が動いたときの額（無ければ 0） |

- **表示用の文は記録するときに作って保存する。** タイトル画面から開くときは本編のアセット（イベント・特性の定義）が無いので、あとから ID で引けないため。

### 5.2 記録するもの

| 種類 | いつ | どこから受け取るか | 状態 |
|---|---|---|---|
| イベント | イベントで選択肢を選んだとき（タイトル＋選んだ選択肢） | `EventManager.OnEventResolved` | **丸山さんに追加を依頼中**（[../team/request-maruyama-event-notify.md](../team/request-maruyama-event-notify.md)・M4） |
| 特性が付いた | 付いたとき | `PersonStatus.Traits.OnChanged`（前回との差分で判断） | 既存 |
| 状態が付いた | 付いたとき（外れたときは記録しない） | `PersonStatus.Conditions.OnChanged`（差分） | 既存 |
| 趣味を見つけた | 趣味の種類が変わったとき | `ChildStatus.OnHobbyChanged` | 既存 |
| 支援を受け始めた | 状態が「受給中」になったとき（毎月の入金は記録しない） | `SupportManager.OnStateChanged` | 既存 |
| 役職が上がった | 月給が変わったとき | `ParentStatus.OnSalaryChanged` | 既存 |
| 赤字の警告 | 赤字の月が始まったとき | `BankruptcyWatcher` | 既存 |
| 将来の夢 | 夢が決まったとき | 夢の仕組み（ending.md 5.3） | 未実装 |
| 受験・進路・浪人・留年 | 合否・進路決定・浪人・留年のとき | `PathSystem` の通知（ending.md 依頼3・4） | 未実装 |

- 毎月の入金・毎日の値の変化は記録しない（数が多すぎて読めなくなるため）。
- 状態（風邪気味など）は同じものが何度も付く。振り返りでは、**同じ文が続いたら「風邪をひいた ×3（4歳）」のようにまとめて表示** する（記録はまとめない）。

### 5.3 画面

振り返りの縦スクロールの一番下に並べる。行は「年齢｜文｜金額」。年齢の区切り（0〜5歳／小学生／中学生／高校生／卒業後）ごとに見出しを入れる。絞り込みは今は作らない（行が多すぎたら考える）。

## 6. データとクラス

### 6.1 EndingResult に足す項目（result-scene.md 3章への追加）

| 項目 | 内容 |
|---|---|
| `mother` / `father` | `ParentResult { rank, salary, stress, workStyle }` |
| `familyLine` | 家計の一文 |
| `parentingLine` | 子育ての一文 |
| `deficitMonths` | 赤字だった月の数 |
| `monthly` | `List<MonthlySnapshot>`（4章） |
| `lifeLog` | `List<LifeLogEntry>`（5章） |
| `ledgerYears` | `List<LedgerYearSummary>`（Ledger の年ごとのまとめを0歳〜終わった歳まで写す。家計のページ用） |

すべて JsonUtility で保存できる型（`[Serializable]` のクラスと List）にする。

### 6.2 保存を2つに分ける（result-scene.md 5章の変更）

記録が入ると1件が数十KBになる。一覧を出すたびに全件の詳細を読むと遅くなるので、

| ファイル | 中身 |
|---|---|
| `records.json` | 一覧用の **概要だけ**（終わった日時・名前・終わり方・職業・年齢・子育てにかかったお金・家出の有無・詳細ファイルのID） |
| `records/<id>.json` | 1件ぶんの **EndingResult 全部**（振り返りで開くときだけ読む） |

ID は終わった日時から作る（`yyyyMMdd_HHmmss`）。

### 6.3 クラス（機能ごとに分ける）

| 名前 | 種類 | 置き場所 | 役割 |
|---|---|---|---|

## 7. 決めないといけないこと

- **イベントの通知**：`EventManager.OnEventResolved` を丸山さんに足してもらう（依頼文：[../team/request-maruyama-event-notify.md](../team/request-maruyama-event-notify.md)）。足すまでは、できごとの記録にイベントが入らない
- 家計の一文・子育ての一文の **数値**（3章はたたき台）。デバッグツールの年齢ジャンプで何回か通して、文がばらけるか確かめてから決める
- `end` シーンの仮の UI は、グラフを細い Image の集まりで描いている（見た目の確認用。シーンが重い）。`LineGraphUI` を作ったら差し替える
- 育成記録（タイトル）から開いたときの家計簿：年ごとの行を詳細ファイルに写して見られるようにするか、ボタンを隠すか（3.5）
- 家出・家計破綻のときの見た目（色・隅の絵）
- 四隅の下側にも枠を置くか
- 育成記録の詳細ファイルの **件数の上限**（無しのままで良いか。1件数十KB）
