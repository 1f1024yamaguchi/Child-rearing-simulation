# 調査メモの置き場所

> メンバーが**現実の制度・お金について調べたこと**を気軽に書き込む場所。
> **ここに書かれた内容は仕様ではない。** ゲームに入れる値は、山口が確認して `docs/design/` に転記したものだけが正。

---

## 1. 書き込み方（3ステップ）

1. 書きたいテーマのファイルを開く
   | テーマ | ファイル | 担当 |
   |---|---|---|
   | 子育てにかかるお金（費目・金額） | [expenses.md](expenses.md) | 有坂さん |
   | 子育て中に起きるイベント | [events.md](events.md) | まるさん |
   | 支援制度（手当・助成・預かり・休暇など） | [support-systems.md](support-systems.md) | あすとさん |

   - どれにも当てはまらないテーマ → [_template.md](_template.md) をコピーして新しいファイルを作る（例：`housing.md`）
2. 表に**1つ調べたら1行**足す
3. コミットして push（メッセージ例：`research: 児童手当を追加`）

### スプレッドシート・メモ帳で調べた人は

表に書き直さなくていい。**元のまま [raw/](raw/) に置く**だけでOK（書き写しは山口がやる）。

- スプレッドシート → **CSV で書き出して**置く（.xlsx は置かない）。1行目を下の2章の列名に揃えると楽
- メモ帳（.txt） → そのまま置く。保存時の文字コードは **UTF-8**
- ファイル名：`<名前>-<テーマ>.<拡張子>`（例：`arisaka-expenses.csv`）
- 詳しくは [raw/README.md](raw/README.md)

### 書き方のゆるいルール

- **必須は「何か（名前と中身）」と「出典URL」だけ。** 分からない欄は空欄でいい。
  - お金：費目名・金額・出典URL
  - イベント：イベント名・何が起きるか・出典URL
  - 支援制度：制度名・どんな制度か・出典URL（金額は分かれば。お金がもらえない制度も書く）
- 自信がない値は末尾に `?` をつける（例：`月1万円?`）。
- 表に収まらないことは、ファイル下の「メモ」に箇条書きで自由に書く。URLを貼るだけでもいい。
- **他の人の行は消さない・書き換えない。** 違う情報を見つけたら、その下に新しい行を足して「備考」に「上と違う」と書く。
- 金額を書くときは**円**で、月額か年額か一回きりかを書く（例：`15,000円/月`、`50万円（一回）`）。

## 2. 列の意味

| 列 | 書くこと | 例 |
|---|---|---|
| 名前 | 制度名・費目名 | 児童手当／保育料 |
| 出どころ | 国／自治体／会社／民間／家庭（支出の場合） | 国 |
| 金額 | 円＋月・年・一回 | 10,000〜15,000円/月 |
| 対象 | 子どもの年齢・時期 | 0歳〜高校卒業まで |
| 条件 | 所得制限など | 所得制限なし（2024年10月〜） |
| 申請 | いつ・どこに・何が必要か | 出生後15日以内に市区町村へ |
| デメリット・注意 | 自己負担・手間・落とし穴 | 申請が遅れた月はさかのぼれない |
| 出典URL | 調べたページ | https://… |
| 確認日 | 調べた日 | 2026-10-21 |
| 書いた人 | 名前 | 有坂 |

支出の表は「申請」の代わりに **「選択制か」**（自動でかかる／選んだらかかる）の列がある。

イベントの表は列が少し違う：

| 列 | 書くこと | 例 |
|---|---|---|
| イベント名 | 何のイベントか | インフルエンザ |
| 何が起きるか | 中身 | 高熱で5日ほど登園できない |
| 時期（年齢） | いつ起きやすいか | 0〜6歳、冬 |
| 起きやすさ | 頻度・割合（分かれば） | 年1回くらい／子の約○% |
| お金 | かかる・もらえるお金 | 診察代 0円（医療費助成あり） |
| 親への影響 | 仕事・ストレスなど | 仕事を休む、看病で睡眠不足 |
| 子への影響 | 体調・気持ちなど | 体調が悪い、友だちと遊べない |
| 対処・使える制度 | どう乗り切るか | 病児保育、看護休暇 |

## 3. ゲームに入れるまでの流れ（山口がやる）

```
docs/research/raw/（元ファイル・形式自由）
   ↓ 山口が表に書き写す
docs/research/（調査メモ・誰でも書ける）
   ↓ 山口が確認・採用する値を決める
docs/design/support-systems.md / expenses.md / events.md（仕様・たたき台）
   ↓ 必要なら docs/decisions/ に理由を残す
Unity の ScriptableObject（ゲームで実際に使う値・これが正）
```

- `raw/` から書き写した行は、「備考」に元ファイル名を書く（例：`raw/arisaka-expenses.csv より`）。`raw/` のファイルは消さない。
- 採用したら、その行の「備考」に `→ 採用済み（design/expenses.md 6章）` のように書く。
- 採用しなかった行も消さない（なぜ入れなかったかが後で分かるように、備考に一言）。

## 4. AI エージェント向け

- このフォルダ（`raw/` を含む）の内容を**仕様として実装に使わない。** 数値の根拠を調べるときの参考資料としてだけ読む。
- ここの値と `docs/design/` の値が違う場合は `docs/design/` が正。食い違いに気づいたら人間に知らせる。
