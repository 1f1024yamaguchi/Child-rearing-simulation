# スポットライト型システムチュートリアル（暗幕くり抜きとプレイヤー操作誘導）の導入

## 背景
ゲーム開始直後に、HUD上の数字・文字（お金、日付、成長ゲージ）や主要な3大機能（サポート制度、カレンダー、家計簿）の役割をプレイヤーに分かりやすく伝えるチュートリアルが必要となった。
その際、プレイヤーがどこを見ればよいかを直感的に伝えるため「説明するボタン周り以外を暗くする」こと、および「実際にボタンを押して画面を開かせるが、他の無関係なボタンを押して誤動作しないように一時的に操作を制限する」ことが求められた。

## 決定
1. **スポットライト方式の採用**:
   - 4枚の暗幕パネル（Top, Bottom, Left, Right）で対象UIの RectTransform を囲み、対象部分だけをくり抜く。
   - 4枚の暗幕パネルは `raycastTarget = true` とし、くり抜かれたボタン以外の画面領域のタップを完全にブロックする。
   - 穴の周囲にはパルス点滅するハイライト枠線（FocusBorder）を表示し、注目箇所を際立たせる。
2. **プレイヤー操作誘導と安全制御**:
   - 「ボタンを押してみましょう！」のステップでは、対象ボタンへのクリックリスナー登録によって、プレイヤーがボタンを押した瞬間に画面が開き、チュートリアルも自動で中身の解説ステップへ遷移する。
   - ポップアップ側には「スキップ」および「次へ（スキップ）」ボタンを常に用意し、絶対に進行不能（ソフトロック）にならない構造にする。
3. **時間停止の遵守**:
   - チュートリアル実行中は `GameClock.I.PushPause()` でゲーム時間を停止し、完了・スキップ時に `PopPause()` で再開する（0004・0011に準拠）。
4. **自己修復・配置の柔軟性**:
   - メニュー「子育て → チュートリアル → スタートガイドを作成・設定」からエディタ上で配置できるほか、シーン上に未配置でも実行時にフォールバック動的生成される仕組みとする。

## 検討した他の案と、採らなかった理由
- **全画面暗幕＋反転ステンシルシェーダー案**:
  - シェーダーの変更が必要で、URPの描画順やWebGL等の環境でステンシルバッファ競合や描画崩れのリスクがあるため不採用。
- **全画面暗幕＋対象UIの Canvas OverrideSorting 案**:
  - 対象UIの階層（LayoutGroupや親のマスク）によってレイアウト崩れが起きやすく、Zオーダーの破綻リスクがあるため不採用。

## 結果・影響
- `Assets/Kusao/TutorialGuide/` に以下のスクリプトを新設：
  - `TutorialGuideStep.cs`: ステップ定義
  - `TutorialGuideSpotlight.cs`: 4枚パネルによる暗幕・くり抜き・タップ制限
  - `TutorialGuidePopup.cs`: 説明ポップアップ・上下自動レイアウト
  - `TutorialGuideController.cs`: チュートリアル進行・画面開閉・時間停止
  - `Editor/TutorialGuideSetup.cs`: シーン構築・設定メニュー
- プレイヤーは迷うことなく基本機能（お金、日付、成長ゲージ、サポート、カレンダー、家計簿）を理解してゲームを開始できる。
