# ターン制ではなくリアルタイム進行にする

## 背景

初期構想（[../design/concept.md](../design/concept.md)）では時間の進み方が未定で、「1ターン＝1ヶ月」のターン制も候補だった。一方、食事の選択や給料の精算は「月に一度」という前提で設計されていた。

## 決定

- **1秒 = ゲーム内1日** のリアルタイム進行にする。ターン制は採らない。
- **30日 = 1ヶ月**で月次処理（イベント抽選・食事選択・収支精算・ステータス更新）をまとめて行う。
- **7300日 = 20歳**でエンディング。
- バランススライダー（親＝ライフ⇔ワーク／子＝勉強⇔遊び）は月をまたがず**いつでも調整できる**。

実装側の `GameClock.secondsPerDay = 1` / `GameState.GoalAgeDays = 7300` と一致している（[../code/architecture.md](../code/architecture.md)）。

## 検討した他の案と、採らなかった理由

- **完全なターン制（1ターン＝1ヶ月）** … 「毎月ボタンを押す」だけの作業になりやすく、子育ての時間が流れていく感じが出ない。
- **完全なリアルタイム（月次処理なし）** … 食事の選択や給料など、月単位でしか意味をなさない要素が扱えない。

→ **時間はリアルタイムで流れ、決断は月単位**というハイブリッドにした。

## 結果・影響

- 20歳到達まで 7300秒（約2時間）かかる。**テンポが適切かは未検証**で、速度設定によるチューニングの余地を残している。
- 月次処理を発火させる仕組みは `MonthTicker.OnMonthChanged` として**実装済み**で、給料日の精算がこれを購読している。イベント抽選・食事選択は未購読。→ [../code/architecture.md](../code/architecture.md)
- 実装の1ヶ月は実際の暦（28〜31日）で、仕様書の「30日 = 1ヶ月」とずれている。→ [../code/architecture.md](../code/architecture.md) 2章
