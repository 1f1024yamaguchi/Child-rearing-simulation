# ストレスは人ごとに持ち、全員に及ぶ効果は一律に適用する

## 背景

ストレスは **母親・父親・子ども がそれぞれ持つ**。子どものストレスが限界になると家出＝ゲームオーバー、という失敗条件の要でもある。

一方で、食事の選択画面を作る中で不自然さが出た。**家族全員で同じものを食べているのに、人によってストレスの増減量が違う**（親 −10／子 −8 など）のは、プレイヤーから見て理由が説明できないし、選択肢カードのチップも無駄に増える。

## 決定

- **ストレスは人ごとに持つ**（母親・父親・子ども、各 0〜100）。この方針は変えない。
- **全員に等しく及ぶ効果は、全員に同じ量を適用する。** 食事がこれにあたる。「高級な食事＝ストレス −5」なら、母親も父親も子どもも一律 −5。
- **特定の人にだけ効く効果は、対象を指定する。** 例：看病で親のストレス +、子どもの成功体験で子のストレス −。

つまり一本化するのは**ストレスの持ち方ではなく、全員に及ぶ効果の書き方**。

## 実装への落とし方

効果（`Effect`）に**対象（target）**を持たせる。→ [../design/effects.md](../design/effects.md)

```
高級な食事        : [ Stress -5 → Everyone, Money -150000 ]
「病院に行く」    : [ Money -8000, Health +15 → Child ]
「家で様子を見る」: [ Stress +8 → Child ]
一時預かり保育    : [ Stress -10 → Parents, Stress -5 → Child, Money -2000 ]
```

`Everyone` を1行書けば全員に同じ量が入るので、食事側で3人ぶんの数値を並べる必要がない。

## 検討した他の案と、採らなかった理由

- **ストレスを世帯にひとつへまとめる** … 確かに単純にはなるが、**家出＝ゲームオーバーという失敗条件が成立しなくなる**。「親は平気だが子が限界」という状況こそがこのゲームの緊張感なので、まとめてはいけない。
- **食事だけ人ごとに違う値を持つ（当初の表）** … 同じものを食べているのに差がつく理由を説明できない。

## 結果・影響

- 選択肢カードのチップは、対象が分かる形で出す（「親ストレス −10」「子ストレス −5」）。全員対象のときは「ストレス −5」の1つで済む。
- `GameState.Stress`（世帯にひとつ）と `ParentStatus.stress`（親ごと）がコード上に並存している件は、**`ParentStatus` 側が正**という整理になる。子どものストレスを持つ入れ物はまだ無い。→ [../code/architecture.md](../code/architecture.md) 3章
