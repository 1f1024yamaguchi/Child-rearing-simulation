# ミニゲームは毎年6月1日・12月1日（0歳6月1日が1回目）に出す

## 背景
半年に1回必ず起きてほしいミニゲームが、起きないことがあった。最初は「通算日数が 183 の倍数ちょうどの日」に出していたため、

- 暦とずれる（183日目は 0歳7月3日）。「半年＝6月」と思って遊ぶと、出るはずの時期に出ない。
- 日付の通知は購読順に呼ばれ、ミニゲームは最後。前の購読者がその日にエラーを出すと通知が届かず、ちょうどの日を逃すと半年分飛ぶ。
- 判断画面で時間を止めても、`GameClock` は同じフレームで残りの日を進めていた（倍速・早送り時に数日ずれる）。

## 決定
1. **0歳6月1日を1回目とし、以降6か月ごと（毎年6月1日・12月1日）に出す。** 暦は `GameDate` で判定する。月・間隔・日は Inspector で変えられる（`firstMonth` / `intervalMonths` / `triggerDay`）。
2. 「ちょうどその日」ではなく「出番の日を過ぎていて、まだ出していなければ予約する」。同じ月のうちに通知が来れば必ず出る。
3. 予約した瞬間に時間を止め（`PushPause`）、ほかの判断画面が開いていない状態（`GameClock.PauseRequests` が自分の1つだけ）が `settleSeconds`（0.3秒・実時間）続いたら出す。食事の選択画面はコルーチンで1フレーム遅れて開くため、すぐ出すと2つの画面が同時に開いてしまった（3倍速で確認）。待つ間も時間は止まっているので、同じ日のうちに出る。
4. ロードで日付が大きく飛んだときは、過去の分はさかのぼらない。
5. `GameClock` に `IsRunning` を追加し、複数日ぶん進めている途中で止められたら残りの日を進めないようにした。

## 検討した他の案と、採らなかった理由
- 183日ごとのまま取りこぼしだけ直す … 暦とずれたまま。プレイヤーには「半年」に見えない。
- `MonthTicker.OnMonthChanged` だけで判定する … 月の変わり目の通知を1回逃すと、その半年分を取り戻せない。
- 食事の選択画面より前（同時）に出す … 2つの判断画面が重なり、どちらを先に操作するか分かりにくい。
