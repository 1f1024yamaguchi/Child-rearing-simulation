# 子どものストレス計算を1日あたりに変更し、カードのストレス段階バッジを廃止する

## 背景

1. **子どものストレス計算のテンポ**：
   子どもの成長計算（成績・趣味・体調・ストレス）を月あたり÷30で毎日適用していたが、ストレス値の動きが緩慢すぎて、勉強に偏らせても危険域に到達するまで数ヶ月〜数年かかってしまい、親の `ParentStressSystem`（日単位）とのテンポ感が合っていなかった。
2. **UI上のストレス段階バッジの冗長性**：
   カード右上に「好調」「注意」などのストレス段階バッジ（`StressBadgeUI`）を設けていたが、カード内には既にストレスゲージ（メーター）が存在し、情報として重複していた。また、風邪気味などの「状態（Condition）」バッジと混同されやすい課題もあった。

## 決定

- **子どものストレス計算を「1日あたり」に変更する**。
  - 成績・趣味・体調はこれまでどおり 1ヶ月あたり÷30 のまま維持する。
  - ストレス計算は 30 で割らず、そのまま毎日適用する（勉強 +5 / 遊び −5 / 親ライフ −1 / 親ワーク +2 / 親過負荷 +1、すべて 1日あたり）。
  - シーンにシリアライズされた旧パラメータとの混同を防ぐため、フィールド名を新しくする（`stressPerDayAtStudy` 等）。
- **ストレス段階バッジ（`StressBadgeUI`）を廃止する**。
  - ストレスはゲージで十分に視認できるため、バッジスクリプトを削除する。
  - `ChildCardUI` および `ParentCardUI` から `stressBadge` への参照と処理を取り除く。

## 検討した他の案と、採らなかった理由

- **成績や趣味などもすべて1日あたりにする** … 成績や趣味経験値は月次で考えたほうが設計・バランス調整がしやすいため、ストレスのみ日次単位に揃える（親ストレスと同じ）。
- **ストレス段階バッジを残し、デザインを調整する** … ゲージと重複しておりカード内の情報過多を招くため、不要と判断して廃止した。

## 結果・影響

- 子どもの勉強⇔遊びバランスを勉強側に寄せた際、約10〜20日で危険域に届くようになり、親のストレス進行と合わせた適切なゲームテンポになった。
- カードUIが整理され、将来の「状態（Condition）」表示との混同が解消された。
- 影響ファイル：
  - `Assets/Yamaguchi/Scripts/Core/ChildGrowthSystem.cs`
  - `Assets/Yamaguchi/Scripts/UI/ChildCardUI.cs`
  - `Assets/Yamaguchi/Scripts/UI/ParentCardUI.cs`
  - `Assets/Yamaguchi/Scripts/UI/StressBadgeUI.cs`（削除）
  - `docs/design/child-status.md`
