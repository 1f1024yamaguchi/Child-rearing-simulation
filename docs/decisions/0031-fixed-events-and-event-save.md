# 固定イベントを抽選と別に持ち、イベントの状態をセーブする

## 背景

誕生日・初めての言葉・お年玉のような「決まった時期に必ず起きる」イベントが、月ごとの抽選（[0030](0030-monthly-independent-event-lottery.md)）では作れなかった。また「1回だけ起きる」ことを守るには、起きた記録が要る。記録をセーブしないと、ロードで同じイベントがもう一度起きる。

## 決定

- `EventData` に `trigger`（`Random` / `Fixed`）と、固定イベントの日付（月・日・満年齢の最小〜最大）を持たせる。固定イベントは抽選の候補に入れず、日付が来たら必ず起こす。
- 満年齢の範囲が1つの値なら1回だけ、範囲なら毎年起きる。
- 起きた記録は「イベントid@歳」の文字列で持つ。
- 同じ日に複数重なる、またはダイアログが開いている間に日が来たイベントは、捨てずに順番待ち（キュー）にする。悪い1・良い1を1組にして、閉じたあとに出す。抽選で予約日にダイアログが開いていた場合も、これまでのように捨てず、順番待ちにする。
- `EventManager` が `ISaveParticipant` になる（キー `"event"`、`RestoreOrder` 110）。固定イベントの記録、今月の抽選済みの印と予約、直前に出したイベント、発生率の補正を保存する。出番待ちは保存しない。

## 検討した他の案と、採らなかった理由

- 固定イベントを抽選の確率100%の特別な枠として扱う … 日付と年齢の範囲を持てず、毎年のイベントも「起きたか」の記録も作れない。
- 重なったイベントを捨てる／どちらかだけ出す … 誕生日のような固定イベントを取りこぼす。
- 1回だけの記録を `GameState` に置く … イベント専用の値で、共通の土台に置くほどのものではない。AGENTS.md ルール3に沿い、イベントの担当（`EventManager`）が持つ。
- 日付をイベントの発生条件（`EventConditionSO`）として表す … 条件は「出してよいか」を判定する部品で、「いつ起こすか」を決めるものではない。

## 結果・影響

- [0029](0029-event-rate-store-and-conditions.md) の「補正はセーブに含めない」と、[0030](0030-monthly-independent-event-lottery.md) の「予約はセーブしない」は、この決定で置き換わる（保存する）。
- `EventData` / `EventManager` / `EventRateModifiers` を変更。固定イベント5件を追加。
- [events.md](../design/events.md) 7章に追記。[save-system.md](../design/save-system.md) の丸山の行を更新。
