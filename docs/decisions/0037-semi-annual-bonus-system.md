# 6月・12月の賞与（ボーナス）支給と源泉徴収税額算出モデル

## 背景
毎月の給与（手取り収入）とは別に、日本の一般的な賞与支給慣行（夏・冬のボーナス）をゲーム内に導入することが求められた。
具体的な賞与の支給額・税額の算定にあたっては、現実の所得税法（財務省告示第115号別表第三）に基づく『賞与に対する源泉徴収税額の算出率の表（令和8年分 甲欄）』（`docs/research/raw/syouyo-zeiritu.md`）に準拠し、子どもの年齢（16歳未満／16歳以上）に応じた扶養親族数の判定を行う仕様が必要となった。

また、情報取得・算定のタイミングと、実際の口座振込・記録・通知のタイミングを現実の給与支払実務に合わせて分離し、「6月・12月に情報を取得・算定し、翌月の7月・1月にそれぞれ振込・家計簿記録・通知を行う」2段階モデルを採用した。

## 決定
1. **進行スケジュール（算定と支給の分離）**:
   - **夏季賞与**:
     - 6月1日：先月（5月）の給与実績等の情報をもとに賞与手取り額を算定・確定し、「7月支給予定」として保留（Pending）。
     - 7月1日：保留された夏季賞与を実際に口座振込・家計簿記録・トースト通知。
   - **冬季賞与**:
     - 12月1日：先月（11月）の給与実績等の情報をもとに賞与手取り額を算定・確定し、「1月支給予定」として保留（Pending）。
     - 1月1日：保留された冬季賞与を実際に口座振込・家計簿記録・トースト通知。

2. **賞与手取り額の計算手順（父母それぞれについて実施）**:
   - **先月の給料（額面）**: 各親の前月給料実績（初期値等は `ParentStatus.MonthlySalary`）。
   - **社会保険料**: `TaxManager.I.Table` の `socialInsuranceRate`（約15%）を乗じた金額。
   - **①（社会保険料等控除後の給与額）**: `先月の給料 − 社会保険料`
   - **扶養親族等の数の判定**:
     - 子どもが16歳未満（`< 16`）：扶養親族数は **0人**。
     - 子どもが16歳以上（`>= 16`）：扶養親族数は **1人**。
     - 扶養親族数のカウントは父母のどちらか一方のみで、**先月の給料が多い方の親** にカウントする。
   - **税率の導出**:
     - ①の金額と扶養親族数をもとに、`BonusTaxTable`（`syouyo-zeiritu.md` 第5章 甲欄データ・全21段階）から算出率（源泉徴収税率）を導出。
   - **税額および手取り賞与額**:
     - `税額 = Mathf.FloorToInt(① × 税率)` （1円未満切り捨て）
     - `手取り賞与額 = ① − 税額`

3. **反映方法と責務分担**:
   - ルールに従い、`Assets/Arisaka/` フォルダ内（`BonusManager.cs`, `BonusTaxTable.cs`）で完結。
   - 支給は共通モデル `EffectApplier.Apply` を経由し、`EffectKind.Money` として `GameState.I.AddMoney` および `Ledger`（家計簿カテゴリ: `給料`、項目: `賞与（父）`/`賞与（母）`）に安全に記録。
   - `ISaveParticipant`（キー: `"bonus"`）によるセーブ・ロード対応（保留中の賞与データも完全保存・復元）。
   - `[RuntimeInitializeOnLoadMethod]` による自動常駐（シーンの競合・破壊を防止）。

## 検討した他の案と、採らなかった理由
- **案A: 6月・12月の同月内に即時振込する**
  - 算定月と振込月を分けたいという実務的要件（6月・12月に算定、7月・1月に振込）に合わせるため、保留（Pending）を介した2段階モデルを採用した。

## 結果・影響
- 6月・12月に算定されたボーナスが、翌月の7月・1月の給料日と同じタイミングで振り込まれ、家計簿記録と通知が行われるようになった。
- ゲームの中断・セーブを行っても、保留中の賞与データが失われることなく正確に7月・1月に支払われる。
