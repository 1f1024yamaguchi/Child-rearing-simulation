# 月別変動生活費への±5%ランダム変動幅の導入

## 背景
これまで月別生活費マネージャー（`MonthlyLivingExpenseManager`）では、総務省家計調査データ（budget01〜12 東京都区部）の該当月の数値を基準値としてそのまま固定額で引き落としていた。
しかし、現実の生活費（光熱・水道、家具・家事用品、被服及び履物、保健医療、交通、通信、教養娯楽、諸雑費）は、気候の変動や家族の行動によって月ごとに多少の振れ幅が生じるものであり、完全な固定値では毎月の家計のリアリティやゲームとしての面白みに欠けていた。

## 決定
`MonthlyLivingExpenseManager` で引き落とす全8項目について、各月の基準値から **±5%（-5% 〜 +5%）の含み（ランダム変動）** を持たせ、その範囲内の整数からランダムに選ばれた金額を引き落とすようにした。

1. **変動幅の算出**:
   - `minCost = Mathf.RoundToInt(baseCost * 0.95f)`
   - `maxCost = Mathf.RoundToInt(baseCost * 1.05f)`
   - `cost = UnityEngine.Random.Range(minCost, maxCost + 1)`
2. **対象項目（全8項目）**:
   - 光熱・水道
   - 家具・家事用品
   - 被服及び履物
   - 保健医療
   - 交通
   - 通信
   - 教養娯楽
   - 諸雑費
3. **実装の独立性**:
   - 有坂担当の作業領域（`Assets/Arisaka/`）内で完結。
   - `MonthlyExpenseDefinition.GetCostWithVariance(int month, float varianceRate = 0.05f)` を追加し、引き落とし処理時に実行。

## 検討した他の案と、採らなかった理由
- **項目ごとに異なる変動率を設定する案（例: 光熱費は±15%、通信費は±2%など）**
  - 採らなかった理由：ユーザーからの明確な指示が「その値からプラスマイナス５パーセントの含みを与えて。その中の数字がランダムで選ばれるようにして」であったため、まずは全項目一律±5%の明快なモデルを採用した。

## 結果・影響
- `Assets/Arisaka/MonthlyLivingExpenseManager.cs`: 各項目の引き落とし額に ±5% のランダム変動を適用。
- 毎月の生活費に自然な揺らぎが生まれ、プレイヤーが月々の家計の変動をよりリアルに実感できるようになった。
