# 1ヶ月は実際の暦の日数（28〜31日）とし、1年365日で回す

## 背景
仕様書（[../design/rules-and-stats.md](../design/rules-and-stats.md)）は「30日 = 1ヶ月」と書いていたが、実装の `GameDate` は実際の暦の月（31/28/31/30…、うるう年なし）で動いていた（[../code/architecture.md](../code/architecture.md) 2章）。
30日×12ヶ月＝360日となり、1年365日・20歳＝7300日とかみ合わない。カレンダー機能（[../design/calendar-system.md](../design/calendar-system.md)）の月の表示にも影響するため、どちらかに決める必要があった。

## 決定
- **1ヶ月の日数は実際の暦（1月31日、2月28日、3月31日…）。うるう年は無し。**
- 1年＝365日、20歳＝7300日。今の `GameDate` / `MonthTicker` の実装をそのまま正とする。
- 仕様書側の「30日 = 1ヶ月」の記述を実装に合わせて直す。

## 検討した他の案と、採らなかった理由
- 30日固定（1年360日） … 1年365日・20歳7300日と合わず、端数の扱いが必要になる。カレンダーの見た目も現実と違ってしまう。

## 結果・影響
- 月ごとの処理（給料日・食事選択・月初イベント）は「30日ごと」ではなく「**月が変わったとき**」（`MonthTicker.OnMonthChanged`）に起きる。間隔は 28〜31日で変わる。
- **残っている問題**：「1ヶ月あたりの値 ÷ 30 を毎日足す」形の計算は、月によって合計がずれる（2月は 28/30、31日の月は 31/30）。
  - 日給：`ParentStatus.WageDaysPerMonth = 30`（[../code/architecture.md](../code/architecture.md) 4章）
  - 子どものステータスの日次変化（[../design/child-status.md](../design/child-status.md) 3章）
  - → **30 のまま、月ごとの小さな差は許す**（2026-09-23 決定）。2月は月給より少し少なく、31日の月は少し多く積み立つが、1年通すとほぼ月給×12 になる（365/30 ≒ 12.17ヶ月分なので、厳密には年に約1.4%多い）。
