# プレイヤーが判断する画面を開いている間は時間を止める

> ⚠ **「## 実装：停止要求はカウントで管理する」の `PushPause` / `PopPause` は [0011-pause-while-open-component.md](0011-pause-while-open-component.md) に置き換わりました。** 今は画面に `PauseWhileOpen` を付けて表示／非表示するだけです。「判断画面を開いている間は時間を止める」という決定と対象の画面は、この ADR のまま有効です。

> [0003-pause-while-calendar-open.md](0003-pause-while-calendar-open.md)（カレンダーのみ）を、対象を広げて置き換えたもの。

## 背景

1秒＝1日でリアルタイムに進むゲーム（[0001-realtime-time-model.md](0001-realtime-time-model.md)）だが、プレイヤーが**読んで考えて選ぶ**画面がいくつもある。カレンダーだけを止めても、他の画面では「読んでいる間に日が進む」問題が残る。

そしてこのゲームの面白さは、トレードオフを理解した上で選ぶところにある（お金 ↔ 子の幸福、節約 ↔ 体調・成績）。選択肢の効果を読み比べている最中に時間が進むと、**比べること自体が罰になる**。急かされて適当に押すゲームになってしまい、テーマが成立しない。

## 決定

**プレイヤーが判断・入力する画面を開いている間は、ゲーム内時間を止める。** 対象は以下。

| 画面 | 担当 |
|---|---|
| カレンダー（申請期限の確認・メモ） | 草尾 |
| 制度一覧（支援制度の申請） | 草尾 |
| 食事のランク選択 | 有坂 |
| メリット／デメリットイベントの行動選択 | 丸山 |

今後この種の画面を追加するときも、同じ扱いにする。

## 実装：停止要求はカウントで管理する

各画面が直接 `GameClock.SetRunning(false/true)` を呼ぶ作りにしない。画面が重なって開いたとき、**片方を閉じた瞬間にもう片方が開いたままゲームが動き出す**から。

代わりに「今いくつの画面が停止を要求しているか」を数える窓口を1つ作り、0 になったときだけ再開する。

```csharp
// 例：GameClock か、その隣に置くヘルパー
private int pauseRequests;

public void PushPause()   // 画面を開いたとき
{
    pauseRequests++;
    if (pauseRequests == 1) SetRunning(false);
}

public void PopPause()    // 画面を閉じたとき
{
    pauseRequests = Mathf.Max(0, pauseRequests - 1);
    if (pauseRequests == 0) SetRunning(true);
}
```

- **各画面は `PushPause()` / `PopPause()` をペアで呼ぶだけ。** `SetRunning` を直接呼ばない。
- 開くときに `PushPause`、閉じる・選択を確定する時に `PopPause`。**閉じるルートが複数ある画面（×ボタン／決定ボタン／背景タップ）は、どのルートでも必ず `PopPause` を通ること。** 呼び忘れるとゲームが止まったまま戻らない。
- この窓口はまだ**未実装**。誰が作るかは要相談（土台なので Core 側が自然）。

## 検討した他の案と、採らなかった理由

- **止めない** … 選択肢を読み比べるほど損をする。トレードオフを考えさせたいのに逆効果。
- **カレンダーだけ止める（ADR 0003）** … 他の画面で同じ問題が残る。画面によって止まったり止まらなかったりするのは、挙動としても分かりにくい。
- **各画面が `SetRunning` を直接呼ぶ** … 画面が重なったときに破綻する（上記）。

## 結果・影響

- 「1秒＝1日」で流れるのは**何も開いていない通常プレイ中だけ**になる。実プレイ時間と 7300日 の関係は、当初の想定（約2時間）より長くなる。テンポ調整のときはこれを前提にすること。→ [../design/rules-and-stats.md](../design/rules-and-stats.md) 1章
- 時間を止めている間に得をする抜け道は作らない。バランススライダーはいつでも動かせるが、日数が進まないので給与もストレスも動かない（[../code/architecture.md](../code/architecture.md) 4章）。
- 月次処理（給料日・食事選択・イベント抽選）が同じ瞬間に重なったときの順番は**未決定**。イベントの選択中に食事選択も開く、といった状況をどう捌くか。
