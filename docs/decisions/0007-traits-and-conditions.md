# 特殊能力は「永続の特性」と「一時の状態」に分け、どちらも補正として扱う

## 背景

子どものステータス画面を設計する中で、2つの要望が出た。

1. 「風邪気味」のような一時的な不調を、**親にも子にも**付けたい。
2. 「ストレスが上がりにくい」「もらえる給料が5%上がる」のような **特殊能力** も入れたい。

どちらも「ステータスの動き方をずらす」もので、既存の `Effect`（その場で1回だけ値を動かす）では表せない。

## 決定

- **`Trait`（特性・永続）と `Condition`（状態・一時）に分ける。** 中身はどちらも `List<StatModifier>` で同一。違いは残り日数を持つかどうか。
- **どちらも母・父・子の誰にでも付く。** 持ち主は共通の `PersonStatus`。
- **入手経路はイベントに一本化する。** `EffectKind` に `AddTrait` / `AddCondition` を足す。
- **補正はステータスの書き込み窓口の中で掛ける。** `AddStress` / `AddGrade` / `AddHealth` / `DailyWage` など。
- `Effect` に **加算か倍率かの区別**（`ModifierOp`）を足す。特殊能力は倍率で表すものが多いため。

詳細は [../design/traits.md](../design/traits.md)。

## 1本にまとめなかった理由

`Condition` だけ作って「残り日数 0 ＝ 永続」として扱う案も検討した。クラスは1つ減るが、

- UI で「特性の行」と「状態の行」に分けるときに、毎回ふるいにかけることになる
- 残り日数を減らす処理が、減らさないものまでなめることになる
- セーブでも「日数を保存するか」で分岐する
- 呼ぶ側が `AddCondition(勉強が得意)` と書くことになり、名前と意味がずれる

寿命・UI・セーブの3か所で同じ分岐を書くなら、**入れ物を分けたほうが分岐そのものが消える**。補正を合算する処理は両方のリストをなめるだけなので、計算側のコードは1本のまま。

## 効かなくなる書き方（注意）

補正は書き込み窓口の中で掛かるので、**窓口を通さずに値を直接書き換えると、特殊能力が黙って効かなくなる。**
これは AGENTS.md ルール4「`GameState` を経由する」と同じ理由で、人ごとのステータスでも同様に守る必要がある。
