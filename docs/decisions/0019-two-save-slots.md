# セーブはオートと手動の2枠にし、「最初から」ではセーブを消さない

## 背景
タイトル画面（[title-screen.md](../design/title-screen.md)）を作るにあたって、「続きから」でどのセーブを読むかを決める必要があった。
[save-system.md](../design/save-system.md) では「セーブ枠は1つ」としていた（2026-10-09）。しかし枠が1つだと、月替わりのオートセーブが手動セーブを上書きしてしまい、プレイヤーが「ここに戻りたい」と思って保存した地点に戻れない。

## 決定
- セーブは **オート**（`save_auto.json`）と **手動**（`save.json`）の2枠にする。
  - オート：月初の処理（給料・支給・食事など）が全部終わった後に保存する（今の `AutoSaver`）。カレンダーのメモを書いたときもオート枠。
  - 手動：［セーブ］ボタンで保存する。
- 「続きから」を押すと、どちらの枠から再開するかを選ぶ。既定は保存日時が新しいほう。
- 「最初から」を押しても **セーブは消さない**。次にその枠へ保存したときに上書きされる。
- ゲームが終わったとき（ゴール・家出）は、今までどおり **2枠とも消す**。

## 検討した他の案と、採らなかった理由
- 枠1つのまま … オートセーブが手動セーブを上書きしてしまう。
- 手動を複数スロットにする … 学習が目的のゲームで、セーブを使い分ける場面が少ない。画面も複雑になる。
- 「最初から」を押した時点で消す … 誤操作で育成が消える。手動枠に前の育成を残しておけない。

## 結果・影響
- `SaveSystem` に枠を指定する版（`Save(SaveSlot)` など）を足す。引数なしの `Save()` はオート枠にするので、カレンダー（`CalendarManager`）のコードは直さなくてよい。
- `SaveButton` は手動枠に保存するよう変える。
- [save-system.md](../design/save-system.md) 3章の「セーブ枠：1つ」はこの ADR で置き換える。
