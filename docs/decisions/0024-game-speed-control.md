# 倍速機能（通常・2x・3x）の導入と日次処理の完全実行モデル

## 背景
ゲームは実時間 1秒 = ゲーム内 1日 で進行するリアルタイム制をとっているが、子どもの巣立ち（18〜22歳）までプレイすると実時間で約2時間かかるため、プレイヤーのテンポ調整用に倍速機能が求められていた。
倍速進行時においても、食費の日割り引き落とし、日給の積立、親・子のストレス増減、税務イベントなど「裏の1日単位の計算」が一切スキップ・取りこぼしされることなく、毎日確実に計算され続ける仕組みが必要であった。

## 決定
1. **倍速設定**：
   - 通常（1x）：実時間 1秒で 1日進む（既定値）
   - 2x：実時間 1秒で 2日進む
   - 3x：実時間 1秒で 3日進む
2. **実装方式（Time.timeScale連動）**：
   - Unityの `Time.timeScale` を `1.0f / 2.0f / 3.0f` に切り替える。
   - `GameClock.Update()` では `timer += Time.deltaTime; while (timer >= secondsPerDay) { timer -= secondsPerDay; Tick(); }` により、1秒間に消化されるループ回数が正確に 1回 / 2回 / 3回 となる。
   - 1回の `Tick()` ごとに `GameState.AddAgeDays(1f)` が呼ばれ、`DayTicker` は `while (lastDay < day) { lastDay++; OnDayPassed(lastDay); }` により1日ずつ通知を発火する。
   - これにより、食費引き落とし（`MealSystemManager`）や日給積立（`WageAccrual`）、ストレス計算等、裏のプログラムは倍速時でも毎日1日ずつ抜け漏れなく順番に計算される。
3. **一時停止（PushPause / PopPause）との両立**：
   - 判断画面（食事選択ダイアログ、カレンダー等）が開いた際の時間停止は `GameClock.running` フラグで管理されているため、`Time.timeScale` が2xや3xのままでも時間はピタッと止まり、画面を閉じると設定していた倍速のまま再開する。
4. **UIの配置**：
   - 画面上部、年月表示（`Canvas/Day`）のすぐ右横に「通常」「2x」「3x」のボタンを設置（プレハブ `Assets/Arisaka/Prefabs/GameSpeedUI.prefab`）。
   - 選択中の倍率がハイライト（シアン色）表示される。
   - PCキーボードの数字キー `1`, `2`, `3` でも切り替え可能。

## 検討した他の案と、採らなかった理由
- **案A: `GameClock.secondsPerDay` を直接変更する**
  - Yamaguchi管理下の `GameClock.cs` を直接改修する必要があり、他メンバー領域への影響が生じる。また、他の時間連動機能との整合性が取りづらい。
- **案B: 1回のTickで2日分・3日分（`AddAgeDays(2f)` 等）進める**
  - 1フレームで複数日進むと、日次イベントや日割り計算の呼び出し順序・タイミングが崩れやすく、日次ログや表示の整合性が失われるリスクがあるため採らなかった。

## 結果・影響
- プレイヤーは画面上部から手軽に 1x / 2x / 3x を切り替え可能になった。
- 食費・日給・ストレス計算等の内部シミュレーションロジックを一切崩すことなく高速化が実現した。
- スクリプト：`Assets/Arisaka/GameSpeedUI.cs`
- プレハブ：`Assets/Arisaka/Prefabs/GameSpeedUI.prefab`
