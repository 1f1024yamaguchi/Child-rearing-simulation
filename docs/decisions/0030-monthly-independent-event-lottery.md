# イベントは悪い・良いを別々に月ごとに抽選し、確率はストレスと発生率補正で決める

## 背景

イベントの発生は、月初に選んだ食事のグレードだけで回数が決まっていた（安価2回／普通1回／高価0回）。発生時は悪いイベントと良いイベントが必ず1組で同時に出ていた。ストレスは発生に関わらず、食事の発生率補正も反映されていなかった。0〜1歳の2種類しか無く、増やしても出方が変わらなかった。

## 決定

- 月初に食事を選んだあと、その月の抽選を1回だけ行う。**悪いイベントと良いイベントは別々に**抽選する。
- 確率は `clamp((基本確率 + 発生率補正の合計) × ストレス段階の倍率, 0, 上限)`。ストレス段階は家族で一番ストレスが高い人のもの。
- 当たった分は、その月の別々の日に予約する。予約日にその日の条件で出せるイベントを重み付きで選び、当たった側のカードだけ出す。
- 良いイベントはストレスで減らさない。ストレスが高いときの救済は、イベントの発生条件（`StressLevelCondition`）で出す。
- 抽選は月ごとのまま。毎日判定にはしない。
- 年齢の制限は `EventManager` から外し、イベントごとの発生条件（`AgeRangeCondition`）に移す。
- イベントは `Resources/Events` に置けば自動で読み込む。シーンの一覧への登録は不要にする。
- まず0〜5歳のイベントを作る。

## 検討した他の案と、採らなかった理由

- 毎日少しずつ判定する … 月の中でばらけるが、月ごとの食事選択と結びつけにくい。月ごとのまま、と決めた。
- 食事グレードで回数を固定したまま、ストレスで回数を足す … 食事以外の補正（選択肢・特性）を足せない。
- ストレスが高いときは良いイベントも減らす … 悪循環で立て直せなくなる。救済イベントを増やす案を取った。
- イベントをシーンの一覧にだけ登録する … イベントを足すたびに共有のシーンファイルを編集することになる（AGENTS.md ルール5）。

## 結果・影響

- `EventManager` を作り直した。`MealSystemManager` からの呼び出し（`ScheduleForMeal`）はそのまま。
- `EventData` に `weight` を追加。0〜5歳のイベント9件と条件アセットを追加。既存の風邪・一時預かり保育に0〜5歳の条件を付けた。
- 予約と補正はセーブしない。ロードするとその月の分は消える。
