# 学期末テスト・進路を Core に作り、判断の画面はイベントのダイアログで代用する

## 背景

ending.md の進路（学期末テスト・高校受験・進路決定・推薦・一般入試・浪人・留年）は設計だけで、コードが無かった。
進路が無いと職業の候補を絞れず、ゴールも「20歳固定」のままで、巣立ちの年齢が進路で変わらない。
専用の画面（antigravity-ending.md 依頼6）まで作ると大きくなるため、先に仕組みだけを動かしたい。

## 決定

1. antigravity-ending.md の依頼1〜4 を Claude が直接作る（2026-11-18）。
   - `GameState` のゴールを「日数＋ラベル」で持ち、`SetGoal` で変える。既定は高校卒業の翌日（18歳4月1日）。セーブに入れ、ロードでは `LoadValues` より先に戻す。
   - `TermTestSystem`（"academic"）・`PathSystem`（"path"）を Core に置き、`SchoolBootstrap` が本編シーンに自動で作る（StoryBootstrap・EndingFlow と同じ。置き忘れを防ぐ）。
   - 進路のアセットは `Resources/Paths/`（PathSystem をシーンに置かないので Resources から読む）。職業の候補は進路ごとに持つ。
2. **進路の判断・お知らせは、専用の画面ができるまでイベントのダイアログ（EventManager）で出す**（`PathDialogs`）。その場で `EventData` を作って順番待ちに入れ、選ばれた選択肢を `OnEventResolved` で受け取る。
   - 進路を決める：就職／専門／大学／推薦（出願できるときだけ）の最大4択。模試の判定（A〜E）と本人の希望（★）を選択肢に出す。
   - 不合格のあと：浪人／就職／専門の3択。
   - 選ぶ途中でセーブした場合は、ロードのあと出し直す（`ChildPath.pendingDialog`）。
3. 子どもの希望は、将来の夢があれば「夢の職業が候補に入っている進路」、無ければ ending.md 依頼3 の決め方。

## 検討した他の案と、採らなかった理由

- 専用の画面（PathDecisionUI など）を先に作る … 画面の見た目を決めていないので後回し。ダイアログの代用なら、選択肢の数（最大4）にも収まる。
- 進路を決めていない子をどうするか決めず放っておく … 7月の画面に答えないまま2月を過ぎると、そのまま高卒で巣立つ（就職として職業を判定）。

## 結果・影響

- コード：GameDate（学年）、GameState（ゴール）、SaveData・SaveSystem（ゴールの保存）、SupportScheme（年の上限 29）、Core/School・Core/Path（新規）、CareerDefinition（不合格回数の上限）、CareerJudge、EndingResultBuilder（進路の職業の候補で判定）。
- 古いセーブ（ゴールが無い）は、ゴールが 18歳4月1日になる。18歳を過ぎた古いセーブは、次の日にゲームが終わる。
- ダイアログの上に「[メリット]／[デメリット]」の帯が出る（イベントの見た目のため）。専用の画面を作るときに消える。
- 成長ゲージの右端の文字（GoalLabel）は、いまの本編シーンに文字が無いので出していない。
- 学費・予備校代・私立高校の学費は、まだお金に反映していない（依頼8）。
