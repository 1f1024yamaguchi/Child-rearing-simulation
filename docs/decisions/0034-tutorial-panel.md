# チュートリアルは「画像＋見出し＋説明文」のページをデータで持ち、共通の画面で出す

## 背景
[0033](0033-no-runaway-until-elementary-ends.md) で小学生まで家出しないことにしたため、中学入学の日（12歳4月1日）に、ストレスが限界だとそのまま30日後に家出してゲームが終わる。プレイヤーには前触れが無く「12歳でいきなり止まる」ように見えていた。
今後もルール説明（チュートリアル）を同じ形式で増やしたい。

## 決定
1. チュートリアルは **上に画像・下に見出しと説明文** の1形式。ページが複数あれば、画像の枠を**スワイプ**（または矢印）で次のページの画像が横から滑って出て、説明文も切り替わる。
2. 中身は `TutorialData`（ScriptableObject）に**ページのリスト**として持つ。新しいチュートリアルはアセットを足すだけで、画面のスクリプトは触らない。
3. 画面は1つ（`TutorialCanvas`）を共通で使う。**配置は Canvas 上のオブジェクトで決め**、コードは中身を差し替えるだけ。ページの点も Canvas 上の Image。
4. 表示中は時間を止める（0004）。他の判断画面と重ならないよう順番待ちにする。
5. 同じチュートリアルは二度出さない。「見た」はセーブに入れる。
6. **家出のチュートリアル**は、家出の判定が始まる日（`RunawayWatcher.ActiveFromDay`＝12歳4月1日）に1回だけ出す。1ページ。画像はドット絵の差し替え枠。

## 検討した他の案と、採らなかった理由
- ストレスが初めて限界になったときに出す … 小学生のうちは家出しないので、そこで見せても「いつ起きるか」が伝わりにくい。判定が始まる日に出せば「ここから起きる」と結びつく。
- チュートリアルごとに画面を作る … 形式が同じなので、毎回作ると見た目がそろわず手間も増える。
- 画面をコードで毎回組み立てる … Canvas 上で配置を直せなくなる（unity-coding.md「シーンを壊さないために」）。

## 結果・影響
- 実装：[../code/ui-tutorial.md](../code/ui-tutorial.md)
- セーブキー `tutorial`（順番 60）が増えた。
- 12歳4月1日は月初めなので、食事の選択画面を閉じてからチュートリアルが出る。
- 「家出まで ○日」の警告行（子どもカード）は従来どおり。
- 出すタイミングの決め方は [0035](0035-tutorial-timing-in-data.md) で変更（専用スクリプト → データの「出すタイミング」）。
